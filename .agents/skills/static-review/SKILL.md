# 静态题材复盘与板块碰撞工作流（思维优先）

本项目本质是**超短盘面思维逻辑工程**——程序只负责确定性的集合二元映射，**成败完全取决于对“本轮唯一主炒”与“盘面补涨生态”的定性准度**。

## 一、开工必过：盘面裁决五步思维关

动手填任何一条 `decisions.json` 前，必须先按活体方法论 [研究思路与碰撞笔记.md](../../../docs/研究思路与碰撞笔记.md) 与当前机读规则 `data/store/rules/static_rules.json` 过完以下五道思维关（本轮会话尚未读过 [研究思路与碰撞笔记.md](../../../docs/研究思路与碰撞笔记.md) 时，**先完整读取一次**校准盘感）：

1. **定性锚点（首板找线索、二板定题材、封死三四板伪切换）**
   - 首板可能试盘或双挂旧主业；到了二板（含首板后停牌重组、复牌顶二板一字），接力与封单资金已亮明底牌。
   - **必查动作**：同时核对二板 `zt_pool` 简表与 `message_topics`（疑点直查当日 `historical_messages.json` / `sector_ladder.json`）。当简表机械沿用首板旧词、而二板题材消息已明确切入当日全场主线梯队时，**以二板真实发酵主线为准**；二板一旦定性全轮锁死，三四板软件贴边改名一律不改归属。
2. **四大共生群落体感（懂谁和谁一起出来抢水，但底层不粗暴一刀切）**
   - **泛传媒 ↔ AI应用**：废除孤立 `游戏` 主炒；传统抱团归 `文化传媒`，AI漫剧/互动影游/AIGC大潮归 `AI应用`；`影视院线` 主炒按传媒/AI线定，底层附带 `消费` 补涨属性。
   - **大电力 ↔ 智能电网**：缺电/电改大潮中同步出来的电网变压器票，须结合大电力主线审视身位与竞争，不视作真空孤岛。
   - **AI 硬件大周期同源分判**：`芯片` / `通信` / `算力` / `元器件` / `非金属材料` 分开核验，但写逻辑时须穿透干瘪行业词，分清“纯周期品涨价”与“AI服务器机架升级映射”。
   - **消费电子（废除悬空 `端侧AI`）**：AI眼镜/AI PC/穿戴硬件归 `消费电子`；极度警惕挂着 `AI玩具/端侧AI/消费电子` 表皮、实蹭 `机器人` 大潮的寄生票。
3. **三大高频表皮欺骗防坑**
   - **防坑一（双栖寄生分支）**：在 `机器人`、`算力` 等强主线高位顶一字时，低位挂 `消费电子/华为/军工电源/农机汽配/游戏` 表皮的双栖票，只要表层小分支无独立连板梯队支撑且与大主线共振启动，**一律穿透还原为大主线**，严防漏掉头顶一字总龙的实质压制！
   - **防坑二（造芯 vs 算力 vs 电力）**：GPU/ASIC/存储/光刻胶/先进封装/芯片金刚石散热等物理造芯硬件归 **`芯片`**；AIDC智算机房、算力租赁、液冷及围绕AIDC缺电发酵的柴发/HVDC电源/燃机归 **`算力`**；无AIDC映射的传统热电/城燃归 **`电力`**。
   - **防坑三（业绩/摘帽壳穿透）**：剔除业绩预增、ST摘帽、超跌等非题材标签后，结合**近期高辨识度股性记忆**与首二实际带动梯队还原真实产业或地域题材。
4. **资本事项：当期公告时效锁 + 真穿透 vs 炒重组三问**
   - `并购重组` 与 `实控人变更` 统一归 `并购重组`；静态快照中的历史重组/易主/股权标签默认不参与匹配，须结合**当期实锤公告**在本轮有效期内赋予属性。
   - 首二定性严辨“真产业穿透”与“炒并购重组本身”：①国资/财务方化债易主无新业务、或关联方注入传统成熟旧资产、或随并购重组/实控人变更梯队成片上榜而细分产业无涨停潮共振 ➔ 直接定为 **`并购重组`**；②跨界切入硬科技赛道且首二与该产业梯队共振引领 ➔ 穿透至**新产业赛道**（并在本轮有效期内 `attributes.add` 附带当期 `并购重组` 属性；首板未发公告的首板日按时点剥离）。
5. **5 板补涨解构、时点防穿越与停牌双轨正交**
   - **5 板起点与真补涨/蹭股分层**：5 板及以上高标才产生补涨（4 板及以下不出补涨）；命中 5 板+ 高标时，写 `replenishment_basis` 须明确穿透区分**同细分一模一样赚钱效应的“真补涨”**（结合 `目标进板高度 ≤ 老龙首开前最高高度 × 0.70` 审视空间差）与**跨主炒副标签“明蹭”/大合集细分不同“暗蹭”**（消费/化工/金融概念/AI应用尤须拆细分）。
   - 首板日之后才披露的跨界新增属性，严禁被晚近快照倒推污染首板日（须用 `attributes.remove` 锁起止日期剥离）；`2024` 年指定月份按已确认时段例外处理。
   - 5板+高标停牌期间以 `X板停牌` 持续留池产生补涨；候选首/二板后停牌复牌连板的，补涨锁死**停牌前首板日既有属性**，复牌后统治力交给**首开前最后一日压制 + 首开竞争**把关。

## 二、零绕路敏捷作业 SOP（最少工具回合）

### 第 1 步：合并起手（单次命令完成检查、读规则与备料）

将状态检查、当前静态口径读取与批次准备合并为一次调用，避免多轮空转：

```powershell
python -B tools/research_cli.py status; python -B tools/research_cli.py rules; python -B tools/research_cli.py batch-prepare --output data/research/<本批目录> --from-date YYYY-MM-DD --to-date YYYY-MM-DD
```

- 按数量或指定记录准备时，替换参数为 `--limit <N> --year <YYYY>` 或重复 `--record-key "代码|记录日期"`；离线只查本地缺项加 `--offline`。

### 第 2 步：精准阅读与定点下钻（不翻大表、不扫全盘）

1. **只读 `data/research/<本批目录>/brief.json`**：它已汇总待填项 `needs`、首二表现 `first_two`、当日高标池 `high_pool_summary`、属性标签 `attribute_tags` 及待定共享高标 `high_themes_to_decide`。
2. **仅对疑点定点下钻**：当某只高标或候选首二分类模糊、疑似双栖表皮欺骗或涉资本事项时，只定点查看 `facts.json` 对应记录，或直接读取该交易日 `data/kaipanla/raw/<YYYY-MM-DD>/historical_messages.json` / `sector_ladder.json` 核实二板真实催化与梯队身位。
3. **单点查询命令**（替代翻找大文件）：
   - 查单条记录：`python -B tools/research_cli.py research --record-key "代码|日期"`
   - 查个股档案：`python -B tools/research_cli.py stock --code <六位代码>`

### 第 3 步：填写 `decisions.json`（聚焦核心逻辑，不填公告污染）

编辑 `data/research/<本批目录>/decisions.json`：
- **`high_themes[]`**（未定共享高标，同启动轮全库复用）：填写 `main_theme`（起步唯一主炒）与 `basis`（首二分类、发酵梯队与定性逻辑）。
- **`records[].static`**：
  - `main_theme`：本轮唯一真实产业或地域主炒（归并后标准大类名）。
  - `main_theme_basis`：逐条深写首二资金认该主炒的核心盘面逻辑（分类、发酵板块、梯队联动、穿透依据）。
  - `replenishment_basis`：结合首板日高标池，逐条写明构成补涨（对应哪条高标周期延伸）或不构成补涨（独立新起主线/高标真空/与在途高标逻辑绝缘）的盘面逻辑。
  - `additional_evidence`：额外引用的本地原始证据路径（无则 `[]`）。
  - *(注：不再填写 `announcement_pollution`；补涨二元命中、一字压制、潜在竞争对手清单与出生当日补涨题材均由程序自动推导。)*

### 第 4 步：原子提交与核验（单次命令）

```powershell
python -B tools/research_cli.py batch-commit --batch data/research/<本批目录>; python -B tools/research_cli.py batch-verify --batch data/research/<本批目录>
```

### 第 5 步：标准汇报与等待拍板

1. **先给结论总表**：`记录键 | 股票 | 唯一主炒 | 补涨 | 压制 | 潜在竞争对手（只列程序生成的清单） | 待补项`。
2. **逐条列核心逻辑**：唯一主炒逻辑要点、补涨盘面逻辑要点、关键来源路径。
3. **收尾摘要**：本批耗时、未完成缺项、需要用户拍板的分歧点（若有二阶连锁影响主动点明）。等待用户确认后再进入下一批。

## 三、题材修正与时点属性例外速查

1. **修正单个启动轮主炒**（自动级联重算全部受影响记录的补涨、压制、竞争清单与总表）：
   ```powershell
   python -B tools/research_cli.py theme-set --record-key "代码|日期" --theme "主炒大类" --basis "修正逻辑依据"
   ```
   *(加 `--preview` 可先只读预览波及范围。)*

2. **批量修正题材或维护时点属性例外（防快照穿越 / 局部实锤补证）**：
   写入临时输入 JSON 后执行 `python -B tools/research_cli.py derive --input data/research/<输入>.json`（提交成功后自动清理输入文件）：
   ```json
   {
     "themes": [
       {
         "code": "000000",
         "first_board_date": "2025-07-XX",
         "main_theme": "主炒大类",
         "basis": "首二定性依据",
         "sources": ["data/kaipanla/raw/2025-07-XX/zt_pool.json"],
         "attributes": {
           "add": [],
           "remove": ["首板日尚不存在的跨界标签"],
           "from_date": "2025-07-XX",
           "to_date": "2025-07-XX",
           "confirmed_partial": false,
           "basis": "时点剥离或局部确认依据",
           "sources": ["data/kaipanla/raw/2025-07-XX/historical_messages.json"]
         }
       }
     ]
   }
   ```
   *(注：`confirmed_partial: true` 仅用于完整属性快照缺失但原始证据已实锤具备某标签时的肯定命中，严禁据部分属性判非补涨或无压制。)*

3. **沉淀认知**：当用户拍板新的通用归并、时段例外、确认个案或盘面防坑经验时：
   - 机读规则/个案/时段例外更新至 `data/store/rules/static_rules.json`；
   - 通用盘面裁决方法论归并迭代至 [研究思路与碰撞笔记.md](../../../docs/研究思路与碰撞笔记.md)（迭代不堆叠，绝不写个股代码与名称）。
