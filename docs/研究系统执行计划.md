# Ultra Board 统一研究系统执行计划

建立以股票、时点属性和首开事件为核心的本地研究系统。原始数据保存证据，SQLite 研究库维护结构化事实、规则与正式研究结论，总表、买卖表和统计由同一个研究库生成。

本文件是执行 agent 的步骤表、进度表和验收依据。当前交付为执行计划；下表工程步骤均待执行。执行者从第 01 步开始，按依赖推进，每完成一步回填状态和证据。

## 执行目标

在 `D:\Ultra-Board` 完成统一研究系统的实现、现有数据迁移、全量核对和日常入口切换。建立股票基础库、时点属性池、行情与公告事实层、启动轮与一字首开事件、高标及竞争对手池、规则版本、静态与动态研究记录、方案统计，以及统一查询和写入接口。现有两张研究表成为可重新生成的精简展示表。全部现有研究记录、已确认结论和原始证据获得完整映射，重复公共资料归为共享记录，历史修订与对照研究有独立归属，最终交付可持续新增研究的完整系统。

完成以第 18 步验收为准。建库、导入一部分数据、展示样例、生成部分表格分别属于中间阶段。

废弃内容必须在替代验证后实际删除，并清理全部引用；禁止以标记废弃、注释停用、改名或移入遗留目录充当清理完成。

## 工作边界与执行约定

- 单 agent 执行，禁止新建子 agent，禁止新建分支，禁止写测试工程，禁止针对具体股票或日期硬编码研究答案。
- 复用现有 CLI、文件接口和取数工具。采用 Python 与 SQLite 的本地实现，先形成完整查询、写入、导表闭环；本次交付范围为本地数据系统及两个精简结果表。
- 现有 `data/` 原始下载资料原地保留。现有工作区改动纳入基线，执行前记录并保护任务外改动；本次替代完成的废弃内容按清理要求删除。
- 清理范围包括废弃脚本、旧写入入口、重复规则、失效说明、无引用的兼容层、重复派生文件和临时迁移产物。先核对替代实现、有效研究迁移及依赖引用，再实际删除并登记结果。原始证据、有效历史研究与当前有效恢复点按各自用途保留。
- 当前 `AGENTS.md`、两张表中的现行判断口径、用户已确认记录为迁移依据。禁止从已作废的聊天、记忆或旧版本恢复交易逻辑。
- 工程迁移逐项保留现有规则含义与确认结论。发现证据冲突、旧统计差异或历史时点缺项时，登记具体记录及影响范围；既有正式结果保留至对应修订获得依据与授权。
- 工程步骤连续推进，步骤核验通过后进入下一步。新增股票研究或重新判断仍执行 `AGENTS.md` 的逐批流程和用户确认要求；迁移过程的资料分块按技术需要安排。
- 用户既有授权覆盖常规实现、迁移、核对与本计划规定的入口切换。涉及新增交易规则、改变用户已确认结论、清除原始数据的事项，单独列明具体内容并交由用户决定，其余独立工作继续推进。
- 全部项目文本使用 UTF-8。中文文件采用明确编码读写并检查乱码。数据库字段类型、价格精度、日期时区、空值语义在第 02 步统一定义。

## 关键实现要求

### 全字段迁移与真实数据核对

第 02 步生成的映射表逐项包含旧文件、字段路径、记录键、字段语义、目标对象和处理方式。对变动字段保留旧值、目标值及转换理由。说明文字、临时扩展字段、旧统计与对照研究也要登记。

迁移原文档案用于留存出处。正式判断、关键事实和关系进入可查询结构；长期使用的数据查询由结构表和证据接口完成。未研究记录保留原有空缺。原始确认状态缺失时如实记录，执行者不得补写为用户已确认。

### 证据时点与来源

事实发生时间、资料对应日期、采集时间分别保存。来源具备数据可见时间证据时额外记录。当前属性快照的日期原样保留；历史查询通过适用范围与已有历史确认选择证据。

针对不同字段迁移当前已确认的来源职责。证据冲突保存全部相关来源与采纳依据。价格统一采用明确的十进制定点表达或等效精确存储方式；精度与复权模式进入字段契约。时间统一注明 Asia/Shanghai，并保留来源精度。

### 规则与结论版本

每份规则有固定版本；每个正式结论关联所用规则、证据快照、适用事件和方案。人工修订以变更记录新增版本，当前版本指针统一管理。规则变化产生受影响记录清单，既有结论按复核流程更新。

迁移当前口径中的具体股票历史确认时，保存适用股票、日期或启动轮、原文依据和确认来源。通用归并规则与个案事实各归其位，原有含义完整保留。

### 读写接口与增量执行

提供以下最小完整能力，并在实际实现后写出可直接运行的命令。命令参数从输入数据、数据库和规则版本读取。

| 能力 | 必填或关键输入 | 输出 |
| --- | --- | --- |
| 导入现有数据 | 来源范围、迁移批次、输入校验值 | 导入计数、更新计数、跳过计数、异常位置 |
| 查股票档案 | 股票代码或内部编号 | 身份、历史名称、轮次、事件与资料覆盖 |
| 查时点属性 | 股票、研究日期、证据使用方式 | 属性、原标签、归并版本、适用状态和证据 |
| 查股票池 | 池类型、日期、规则版本；竞争池附候选事件 | 成员、身位、属性查询方向、覆盖状态和依据 |
| 查完整研究 | 旧记录键或事件编号、方案 | 当前结论、核查明细、事实、证据与修订 |
| 查缺项与影响 | 日期范围或研究范围、变更对象 | 具体缺项、涉及记录、影响步骤 |
| 写研究结果 | 事件、方案、规则版本、当前记录版本、结果与依据 | 原子提交结果、修订编号、受影响展示 |
| 生成表与统计 | 日期范围、方案、数据快照、输出目录 | 精简 JSON、CSV、统计与生成信息 |
| 核对与恢复 | 基线、目标数据库、恢复点 | 逐项差异、恢复验证及执行记录 |

重复导入按来源内容与业务身份处理；已有相同版本可直接复用，新内容进入新的证据或事实版本。并发写入采用明确锁定或排队策略，版本发生变化时返回冲突及当前版本，避免覆盖其他工作。

### 两表结构与同版本发布

总表建议列为：记录键、股票代码、股票名称、首板日、一字段、首开日、唯一主炒、补涨判断、压制判断、公告污染、研究状态。

买卖表建议列为：记录键、股票代码、股票名称、首开日、方案、竞价结果、卡位结果、买点时间、买入价格、卖点时间、卖出价格、盈亏、研究状态。一个事件存在多条实际记录时增加交易记录编号，保持每行身份清楚。

详细依据使用记录键查询。JSON 可附少量生成信息，CSV 保留清晰列。两表与统计在同一个数据库读快照下生成，先写入独立输出目录，校验后发布同一批次。批次清单标明输入版本、规则版本和文件校验值；读取方核对批次。多文件发布中断时恢复上一完整批次。

### 核验范围

使用现有真实数据执行迁移核对和 SQL 完整性检查，复用或调整现有验证入口。检查包含以下内容：

- 每个基线记录键的映射、字段归属、正式结论和证据引用。
- 启动轮、一字段与首开事件的数量关系；同轮多个机会、尚未首开和历史缺项的保留情况。
- 补涨、压制与卡位各自的查询方向、检查对象和覆盖清单。
- 历史属性的资料时点、快照日期和适用限制。
- 正式方案与对照方案的逐笔结果、样本分母、统计公式和结果。
- 全量导入后重复执行，记录数和内容是否稳定；实际来源有新增版本时的增量行为。
- 隔离副本上的失败回滚、版本冲突和恢复；正式数据中禁止写入演练用结论。
- 代表性真实查询的耗时、完整导入耗时、峰值内存及文件体积。抽样条件从数据分布确定，并记录实际样本键。
- 中文往返读取、编码、空值、日期、价格精度和 CSV 显示。
- 清理清单内的废弃文件与实现已实际删除；正式代码、命令、文档及数据引用无指向已删除内容的残留；清理后的完整流程可运行。

核验工作采用同一执行者完成实现后的独立复查过程，核对实际数据和交付产物。禁止通过新建测试工程扩展任务。

## 切换与恢复条件

第 16 步通过前，正式来源仍为现有两表。执行者在迁移工作区完成建库、导入和生成结果的核对。

第 17 步执行前重新核对输入校验值。源文件若已变化，解析增量并重新核验相关记录；最新正式内容进入迁移结果后建立恢复点。切换时收拢旧写入入口，保证发布过程中单一写入方。

切换恢复点覆盖正式数据库、两张表、规则、相关脚本和项目说明，记录其版本与校验值。失败时恢复同一套版本并验证读写入口。原始下载资料持续保留。

切换验证完成后执行实际清理。有效历史研究与修订依据迁入研究库后，清除其重复工作副本和已被替代的旧实现。恢复材料集中保存当前有效切换恢复点，删除过期副本；交接记录列明保留材料的用途。废弃程序、旧规则和旧入口从日常工程中移除，并检查代码、文档和数据中的引用。

切换后 `AGENTS.md` 的研究顺序、取数方向和每批确认要求继续执行；存储职责、规则读取和写入位置改为新入口。两张表的规则正文迁至规则中心后，项目说明提供实际可运行的规则读取命令。
