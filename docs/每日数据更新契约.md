# 每日数据更新契约

## 唯一入口

```powershell
# 自动刷新并选择开盘啦最近完整交易日
npm run data:update

# 严格更新一个交易日
npm run data:update -- --date YYYY-MM-DD

# 批量回灌闭区间
npm run data:update -- --start YYYY-MM-DD --end YYYY-MM-DD
```

正式事实链只读取开盘啦。历史同花顺文件保留为旧研究证据，但不参与更新、完整性门禁或单日事实组装。

## 单日合同

每个历史交易日落盘到 `data/kaipanla/raw/YYYY-MM-DD/`：

- `sentiment.json`：涨跌家数、涨跌停与市场情绪；
- `expression.json`：开盘啦梯队情绪指标；
- `zt_pool.json`：完整目标市场涨停池、真实连板数、首次封板、成交额、换手率、价格和当日主分类；
- `sector_ladder.json`：开盘啦题材梯队原始快照；
- `_DONE`：上述来源和数量合同全部闭合；
- `_MISMATCH`：来源未闭合，禁止作为正式日读取。

`DailyLimitPerformance` 的每一条源记录必须进入目标市场或明确的北交所排除账；`HisZhangFuDetail.SJZT` 只作不同市场范围的参考，不冒充同口径总数。

## 区间回灌与续传

区间入口只遍历工作日；开盘啦对已过去至少一周的日期明确返回未入库时，记录到 `data/kaipanla/non_trading_days.json`。最近日期的同一响应可能只是历史库尚未发布，不会永久记作休市。已经存在且通过校验的 `_DONE` 日自动跳过，缺失日才发起请求。

网络失败立即停在具体日期；数据不闭合则写 `_MISMATCH` 并在区间结束时统一报告。修复问题后重跑同一条命令即可续传，不需要逐日手写日期，也不会覆盖已经闭合的历史日。

## 完整性门禁

正式日必须同时满足：

- `_DONE` 存在且 `_MISMATCH` 不存在；
- 四个正式JSON文件可读，内部 `date` 与目录一致；
- 涨停池 `count` 与股票数组数量一致；
- 源行数等于正式股票数加明确排除数；
- 每只股票都有代码、名称和真实连板数；主分类缺失时显式为 `null`；
- `build_day_component` 能从该日开盘啦目录即时组装，且 `source_issues` 为空。

故事、同花顺涨停池、最终封板时间、炸板次数、板型、市值和封单不再是正式数据依赖，也不得用默认值或推断值补造。

开盘啦附加概念标签会在历史查询中出现后来概念，原始字段可以保留溯源，正式读取只用当日主分类，防止未来信息泄漏。
