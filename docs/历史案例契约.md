# Ultra-Board 历史案例契约

## 一、文件职责

- [`AGENTS.md`](../AGENTS.md)：跨交易日复用的资金研究思维与角色定义。
- `data/answer/YYYY-MM-DD-连板市场复盘研究报告.md`：以目标日信息截点冻结的单日判断、次日主路径与反向路径。
- `data/cases/records/*.json`：已经得到后一交易日真相的逐案例版本记录，是案例条件、冻结决策、判卷与修订的唯一真相源。
- [`docs/学习训练.md`](学习训练.md)：从已确认案例提炼的人工阅读汇总，不承担逐案例机器真相。
- `docs/学习过程-*.md`：首批结构化案例的迁移来源与历史证据，迁移后不反向覆盖案例记录。
- 本文件：学习案例的字段、时间边界、修订和 RAG 切片合同。
- 本地 Agent API：交易事实的统一真相源；案例和报告均不能反向覆盖接口事实。

## 二、案例时间轴与可用边界

每个案例记录：

- `case_status`：`open` 或 `closed`；
- `setup_trade_date`：形成初始环境和定位契约的交易日；
- `decision_cutoff`：起始日研究可使用信息的截止时点；
- `replay_trade_date`：验证原判断的后一交易日；
- `outcome_cutoff`：案例结果使用信息的截止时点；
- `decision_record_mode`：`contemporaneous` 或 `blind_reconstruction`；
- `decision_recorded_at`：定位报告实际形成的日期或时间；
- `case_compiled_at`：案例切片实际整理时间；
- `historical_replay_scope`：`contemporaneous_evidence` 或 `current_method_only`。

`contemporaneous` 表示定位契约真实形成于验证日之前；`blind_reconstruction` 表示报告在更晚时间重建，但研究过程中隔离了验证日行情。两者都可以用于研究，案例会如实保留记录模式，不把盲态重建冒充成当时已经落盘的决策。通常前者可标记 `contemporaneous_evidence`，后者标记 `current_method_only`。

案例进入当前研究上下文需要同时满足：

1. `case_status=closed`；
2. 默认检索时 `retrieval_status=accepted`；`hypothesis` 只在研究明确需要时作为待验证解释调用，`superseded` 不进入当前判断；
3. `outcome_cutoff` 严格早于当前研究的 `information_cutoff`；
4. 调用时能够区分起始日已知信息、隔夜新增环境和验证日日内信息。

案例有两种使用语境：

- **当前方法研究**：在实际研究时间已经完成整理并验收的案例，只要市场结果截点早于目标日信息截点，就可以用于形成当前方法下的类比；
- **严格同时态回放**：除上述市场时间条件外，还比较 `decision_recorded_at`、`case_compiled_at` 与模拟时点。模拟时点之后才形成的案例不用于证明“当时已经具备该方法”。`blind_reconstruction` 可以检验当前方法，但不冒充同时态交易记录。

## 三、案例字段

每个案例使用一个稳定 `case_id` 表示同一环境—演变案例族，并用 `record_id=<case_id>@<revision>` 唯一标识具体版本；文件名必须与 `record_id` 一致。每条记录包含：

- `revision`：当前修订序号；
- `supersedes`：被本版本替代的旧 `record_id`；
- `retrieval_status`：`accepted`、`hypothesis` 或 `superseded`；
- `source`：迁移或原生记录类型、来源文档、段落哈希、`source_reports`、`data_revision` 和 `source_issues`；
- `case_question` 与只含 T 日条件的 `retrieval_tags`；
- `condition_axes`：发酵、加速、板型和高度四个固定条件轴；
- `market_structure`：是否为节点、断板核心与收盘结构；
- `decision`：攻守模型、防守身位、唯一或条件路径、冻结计划和失效条件；
- `outcome`：验证日事实、是否触板、是否封住、交易判卷和后续反馈；
- `similarity`：适合召回的环境摘要与降低相似度的差异边界；
- **外部信息层**：公开时间、时区、来源类型、语义可靠性及其属于盘前已知、隔夜新增还是日内传播；
- **日内关键序列**：能够改变契约或角色的少量时间点；
- **收盘角色图**：总核心、分支领涨、高度桥、交易载体、回流受益者和外部种子；
- **后续演变与四张判卷**：市场状态、角色、主动时序和交易结果；
- **类比描述**：适合召回的环境指纹、历史后续和降低相似度的差异。

## 四、事实、契约与解释分层

日内关键事件采用三层表达：

- **事实**：时间、板数、首次与最终封板、开板次数、换手、封单及来源集合状态；
- **契约判定**：原主路径或反向路径命中、部分命中、失效、无法验证或遇到截点后新环境；
- **角色影响**：强化、受压、升级、未延续、分散承接或仍待确认。

“未进入验证日最终涨停来源集合”只证明对象没有收涨停。接口不提供池外完整行情时，案例不补写竞价、开高低收或盘中强弱。

角色退出与风险因子退出分别记录。原分支领涨未延续，而同属性纵向和容量仍增强，描述为载体更换或分散承接；原领涨、低位梯队和属性广度同步收缩时，再描述为分支衰退。

## 五、外部信息记录

每条关键外部信息尽量包含：

- `public_at` 与时区；
- 来源类型：政府、交易所、公司、权威媒体、本地市场故事或时间未核验的媒体传播；
- 原文链接或本地接口路径；
- `availability`：`before_decision_cutoff`、`between_cutoff_and_open`、`during_replay_confirmed`、`known_by_replay_close` 或 `same_day_public_time_unverified`；
- 对市场的作用：原预测依据、隔夜新环境、旧信息重新定价或低可靠故事。

无法闭合精确发布时间时标记 `public_time_unverified`。市场故事仍可用于解释资金传播，但不升级为公司或政策事实。

## 六、RAG 切片与修订

`data/cases/records/*.json` 保存完整案例，不因向量模型长度删减关键时序。`tools/case_library.py export-chunks` 从同一记录生成两种派生文本：`retrieval_text` 按字段白名单读取条件标签、四个条件轴、节点结构和冻结路径，用于相似度计算；`text` 包含条件、决策与历史结果，供召回后阅读。验证日结果、成功、无交易、吃面和隔日反馈不得进入 `retrieval_text`；旧标题、案例问题和相似性复述也不进入该字段，避免历史标题中的后验措辞泄漏。

案例召回依赖环境、角色、阶段和时序标签，不以股票名称或最终涨跌作为主要相似度。检索结果同时返回相似条件、差异边界和历史后续，供当前研究形成条件路径。

事实或解释需要修正时保留旧版本，沿用 `case_id`、增加 `revision`，生成新的 `record_id`，并通过 `supersedes` 指向旧 `record_id`；旧版本标记为 `superseded`。同一 `case_id` 同时只能存在一个未被替代版本。Markdown 阅读稿、向量索引和搜索缓存都是可重建派生物，不反向改写案例。

结构、修订链、时间边界和条件/结果标签隔离统一由以下命令验收：

```powershell
python tools/case_library.py validate
```

中文 Markdown 采用 UTF-8 无 BOM，链接使用相对项目路径或可核验公开地址。
