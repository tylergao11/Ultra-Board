# 五日动态事实包契约 v1

本契约定义 Ultra-Board 面向后续 LLM 的只读动态数据接口。输出是可重建的
派生事实包，不是新的行情真相源，也不输出交易判断。

## 一、证据边界

- 必须显式提供 `information_cutoff=T`。
- 窗口默认包含 T 日及之前四个本地交易数据日。
- 任何日数据缺失必须进入 `coverage`，不得跨过缺口伪造连续关系；只有同花顺
  `consecutive_limit_up_dates` 明确给出个股连板日期链时，才允许在独立的
  `board_sequence_facts` 中连接跨空档板数。
- 动态路径从首板开始；`1→2` 与所有更高板数变化使用同一事实合同。
- 股票未出现在某日涨停池不等于失败或停牌；没有正式停牌字段时禁止补写
  `suspended=true`。
- 禁止读取 `.blind-test-quarantine/`。
- 禁止输出爆发、打断、对手、皇位继承、高低切、接力、反攻、核心、
  评分或买点结论。

## 二、字段唯一来源

| 数据 | 唯一来源 |
|---|---|
| 个股默认主属性 | 开盘啦 `stocks[].theme` |
| 个股全部候选属性 | 开盘啦 `stocks[].raw[12]`，读取为 `themes` |
| 开盘啦板块梯队 | `sector_ladder.json` |
| 市场情绪与表达 | `sentiment.json`、`expression.json` |
| 板数、板型、真一字、封板过程、价格、市值、换手与封单 | 同花顺 `limit_pool` |
| 个股来源连板日期链 | 同花顺 `limit_pool` 的 `boards_source`、`consecutive_limit_up_dates` |
| 当日板块故事与可选个股故事 | 同花顺 `stories` |

同花顺故事不得覆盖或补造开盘啦个股属性。`reason_type` 不进入本接口。

## 三、查询合同

逻辑接口：

```text
get_replay(
  date,
  window_size=5,
  themes=[],
  include_all_first_boards=false
)
```

### 1. 默认市场模式

未传 `themes` 且 `include_all_first_boards=false`：

- 每日 `days[].stocks` 只展开全市场二板及以上股票；
- 二板以上只是每日明细展示阈值，不是动态路径的起点；
- 凡窗口内任一日进入二板及以上的股票，`stock_paths` 必须使用该股票在
  窗口内的全部来源记录，自动回带可用的首板起点；
- `board_sequence_facts` 必须完整保留 `1_to_2`，不得因首板未进入当日
  `stocks` 或中间存在个股非交易空档而截断一进二；
- 尚未进入二板的首板个股不进入默认 `days[].stocks`；
- 仍返回每日全市场首板数量和紧凑源属性索引；
- 本地首板原始数据不得删除或过滤出存储层。

因此，“已发生的一进二自动返回”与“尚未晋级的首板按需展开”同时成立。

### 2. 题材模式

传入一个或多个 `themes`：

- 在开盘啦 `theme/themes` 中进行字符串精确匹配；
- 多题材使用并集；
- 返回命中题材的全部涨停股票，包括首板及所有更高板；
- 每只股票返回具体命中项及命中来源 `main/candidate`；
- 一只多属性股票可以被多个题材查询同时返回。

### 3. 全市场全板数模式

只有显式设置 `include_all_first_boards=true` 时，才返回全市场全部涨停股票。

### 4. 向前推进

```text
next(cursor, themes=[], include_all_first_boards=false)
```

- 推进到下一个本地数据日；
- 保持原查询范围不变；
- 新窗口仍为五日；
- 新结果使用新的 `information_cutoff`，不得改写旧窗口结果。

## 四、顶层输出

```json
{
  "schema_version": 1,
  "view": "five_day_dynamic_facts",
  "information_cutoff": "2026-07-24",
  "trade_dates": [],
  "window_start_boundary": "outside_window_unknown",
  "scope": {},
  "source_contract": {},
  "coverage": {},
  "days": [],
  "stock_paths": [],
  "board_sequence_facts": [],
  "transition_facts": [],
  "continuation": {}
}
```

## 五、每日事实

每个 `days[]` 必须提供：

- `coverage`：开盘啦、同花顺涨停池、同花顺故事的独立覆盖状态；
- `market`：全市场涨停数、首板数、二板以上数量、板数分布、最高板及
  全部并列持有者、情绪与表达原文；
- `stories`：同花顺当日故事原始记录；
- `source_sector_index`：开盘啦板块名称、代码、源顺序和各高度数量；
- `source_theme_index`：候选属性成员数、首板数、二板以上数量和最高板；
- `stocks_by_board`：当日已展开明细的板数到股票代码索引；
- `expanded_stock_count`：当日已展开的个股数量；
- `stocks`：当日已展开的个股事实，不代表动态路径的事实边界；
- `source_issues`：源缺失、源间股票集合差异及读取错误。

默认市场模式的题材索引只给数量，不展开首板代码。题材模式才展开该题材
全部个股。

## 六、个股事实

每只股票必须保留：

```json
{
  "date": "2026-07-24",
  "code": "002879",
  "name": "长缆科技",
  "attributes": {
    "source_main_theme": "智能电网",
    "source_candidate_themes": ["智能电网", "电气设备", "算力"],
    "source_sector_code": "...",
    "source_is_fanbao": false,
    "matched_attributes": []
  },
  "limit_facts": {
    "boards": 4,
    "boards_desc": "4天4板",
    "first_limit_ts": 0,
    "final_limit_ts": 0,
    "open_count": 0,
    "board_type": "T字板",
    "one_price": false,
    "price": 0,
    "circulating_market_cap": 0,
    "turnover_rate": 0,
    "seal_order_amount": 0,
    "seal_order_ratio": 0
  }
}
```

行情字段缺失时写 `null`，不得使用开盘啦同名行情字段补齐同花顺事实。

## 七、动态路径、市场相邻日与来源连板链

`stock_paths` 的跟踪集合，是窗口内至少有一天进入 `days[].stocks` 的全部
股票。路径状态必须从每日全量来源记录构建，禁止再次使用每日展示阈值过滤。
`transition_facts` 和 `board_sequence_facts` 使用同一跟踪集合，但表达两种不同
时间关系，禁止混成一条时间线。

默认市场模式下，一只股票前一日首板、后一日二板时，路径必须类似：

```json
{
  "code": "000001",
  "expanded_in_day_stocks_on": ["2026-07-24"],
  "states_aligned_to_trade_dates": [
    {
      "date": "2026-07-23",
      "in_day_stocks": false,
      "boards": 1
    },
    {
      "date": "2026-07-24",
      "in_day_stocks": true,
      "boards": 2
    }
  ]
}
```

### 1. 市场逐日观察链

`stock_paths.states_aligned_to_trade_dates` 和 `transition_facts` 严格按窗口内
相邻市场数据日排列。`transition_facts` 中，相邻两日至少一日存在该股票来源
记录时，即使两日都未进入 `days[].stocks`，也必须保留这条相邻日事实。

`in_day_stocks=false` 只表示该记录未在每日明细中展开，不表示该事实不重要。
数组中的 `null` 表示该股票未出现在当日开盘啦与同花顺涨停池的股票并集中；
必须结合当日 `coverage` 使用，不能擅自解释为失败或停牌。

每个相邻交易日的 `transition_facts[].facts[]` 必须提供：

- `from`、`to`：相邻两日可见的来源状态；
- `board_transition`：两侧板数都存在时生成的客观键，例如 `1_to_2`；
- `boards_change`：两侧板数都存在时的算术差；
- `day_stock_view`：只描述该股票是否在两日明细中展开；
- `source_attribute_change`：只有两侧都有开盘啦属性记录时才计算候选属性
  差集；任一侧缺失时必须返回 `comparison_status=not_comparable...`，且
  `added/removed=null`，不得把空档伪装成属性删除或重新增加。

### 2. 个股来源连板链

`board_sequence_facts` 专门表达连板序列。正常相邻市场日的 `1→2` 可以由两日
板数事实连接；跨市场日空档时，必须存在同花顺
`consecutive_limit_up_dates` 明确日期链才能连接：

```json
{
  "code": "002969",
  "name": "嘉美包装",
  "from_date": "2026-01-06",
  "to_date": "2026-01-12",
  "from_boards": 1,
  "to_boards": 2,
  "board_transition": "1_to_2",
  "intervening_window_trade_dates": [
    "2026-01-07",
    "2026-01-08",
    "2026-01-09"
  ],
  "crosses_window_trade_date_gap": true,
  "evidence_basis": ["ths_consecutive_limit_up_dates"],
  "evidence_as_of_dates": ["2026-01-12"]
}
```

市场逐日观察链在这个例子中仍为 `1, null, null, null, 2`；来源连板链则保留
`1_to_2`。两者并不冲突：前者描述每天看到了什么，后者描述同花顺确认的
个股连板日期关系。`crosses_window_trade_date_gap=true` 不自动等于停牌标签。

这些字段不得命名或解释为晋级成功、淘汰、竞争胜负、接力强弱或带动关系。
如果二板股票的首板发生在五日窗口之外，只保留
`window_start_boundary=outside_window_unknown`，不得额外补造第六日。

## 八、同花顺故事合同

### 1. 板块故事

现有记录保持不变：

```json
{
  "source_position": 1,
  "story": "市场并购重组持续活跃；龙头十连板",
  "context": "并购重组",
  "headline": "并购重组：市场并购重组持续活跃；龙头十连板"
}
```

`story` 是可见标题冒号后的故事；`context` 只用于还原标题，不参与个股
属性匹配。

### 2. 个股故事

如同一标题下存在可见的个股故事，在对应 `stories[]` 项内增加可选
`stocks` 数组：

```json
{
  "source_position": 1,
  "story": "市场并购重组持续活跃；龙头十连板",
  "context": "并购重组",
  "headline": "并购重组：市场并购重组持续活跃；龙头十连板",
  "stocks": [
    {
      "stock_position": 1,
      "code": "603221",
      "name": "爱丽家居",
      "story": "同花顺图片中可见的个股故事原文",
      "mapping_status": "matched_same_day_stock"
    }
  ]
}
```

约束：

- `stock_position` 在同一标题内从 1 连续递增；
- `name` 和 `story` 必填；
- 只有能与同日开盘啦或同花顺涨停池唯一对应时才填写 `code`；
- 无法唯一对应时 `code=null`、`mapping_status=unresolved`；
- 个股故事保存可见原文，不生成 `theme`、核心、强弱或买点字段；
- 个股故事只能作为后续 AI 归因证据，不能修改开盘啦 `theme/themes`。

没有个股故事时可以省略 `stocks`，现有故事文件继续有效。

## 九、完整性状态

`coverage.status=complete` 只表示五日开盘啦必需文件和同花顺涨停池均完整。
故事为可选上下文，使用独立的 `story_status`，故事缺失不得伪装成“当天没有
故事”。

源间股票集合不一致时必须保留并报告双方独有代码，不得只取交集后静默丢失。

## 十、编码与写入

- JSON、Python、Markdown 一律 UTF-8 无 BOM；
- JSON 使用 `ensure_ascii=false`；
- 文件写入使用临时文件后原子替换；
- 中文字段不得经过多层内联转义写入。
