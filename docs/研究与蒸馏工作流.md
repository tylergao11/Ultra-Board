# Ultra-Board 研究与蒸馏工作流

本工作流只整理事实和公开决策轨迹，不建立评分模型。目标是让每日判断更快，同时把真实选择、用户揭晓和规则纠错保存为后续蒸馏材料。

## 零、知识使用方式

当前不做模型蒸馏。继续使用主模型推理，外挂知识库只保存逐条确认的总结，
并以一条总结作为一个 RAG 切片：

```powershell
python tools/knowledge_base.py validate
python tools/knowledge_base.py list --tag 一字板 --tag 换手
```

`data/knowledge/summaries.jsonl` 是总结真相源。默认只取回 `accepted`；
`hypothesis` 必须显式请求，`superseded` 只保留纠错轨迹。向量索引以后按需建立，
且只能从该 JSONL 重建。

## 一、每日盲测

### 1. 冻结单日事实

```powershell
python tools/market_memory.py brief 2025-11-06
```

输出只读取 `information_cutoff` 及以前的数据，包括上一梯队去向、当前涨停池、一字/换手状态和身位竞争。默认不按板数排除；`--min-boards` 仅用于减少展示量。它不会输出核心或买点。

同花顺长图仍由人工查看，只读取标题冒号后的故事。脚本不做 OCR，也不把标题前半句或个股事件行写成第二套分类。

### 2. 查看个股连续路径

```powershell
python tools/market_memory.py path 000993 2025-11-06 --start 2025-11-04
```

路径同时展示首封、终封、炸板、换手、一字状态和跨日相对变化。首封提前或换手缩放只作为事实，不自动命名为加速、分歧或核心。

### 3. 查看一字核心角色切换

```powershell
python tools/market_memory.py competition 2025-11-06
```

视图区分：

- 当前仍锁死的一字票；
- 前一日一字、当日已经开门换手的票；
- 前一日一字、当日未能涨停的票；
- 同身位且源属性重合的换手者；
- 源属性不重合、但可能被当日故事临时连接的同身位换手者。

后一类必须由人工依据可见故事判断，禁止建立关键词硬映射。

### 4. 揭晓前记录选择

复制 `data/training/decision_template.json` 为单行 JSON，使用 `apply_patch` 追加到 `data/training/decisions.jsonl`。必须记录：

- 当时信息截止日；
- 候选与最终选择；
- 排除条件；
- 预期个股形态；
- 哪些信息仍然缺失。

```powershell
python tools/training_records.py validate
```

只有完成这一步后，记录才可被称为揭晓前判断。

## 二、用户揭晓与纠错

结果揭晓、错误选择、规则替换和用户确认的最终学习只能进入 `.blind-test-quarantine/distillation/`。日常决策工具没有读取该目录的代码路径。

后验记录使用以下关系保留清洗过程：

```text
真实旧选择 -> outcome_reveal -> correction -> accepted_learning
                  |                |
                  +------ supersedes
```

不删除错误选择，因为“为什么当时会选错、哪条证据改变了结论”本身就是蒸馏样本。记录中的 `public_reasoning_summary` 只包含对话里已公开表达的依据，不保存或生成隐藏思维链。

显式训练导出：

```powershell
python tools/training_records.py export-sft `
  --scope post-outcome `
  --allow-post-outcome `
  --output artifacts/training/conversation_alignment.jsonl
```

该命令不得在盲测判断过程中调用。

## 三、节点记忆池

节点由人工指定，不由脚本自动识别：

```powershell
python tools/market_memory.py pool 2025-11-06 2025-11-06 `
  --output data/research/node_pools/2025-11-06__cutoff_2025-11-06.json
```

后续推进到新的截止日时，重新生成同一节点池：

```powershell
python tools/market_memory.py pool 2025-11-06 2025-11-28 `
  --output data/research/node_pools/2025-11-06__cutoff_2025-11-28.json
```

每个成员保留：节点日身份、以后再次涨停日期、连续主升或中断再激活、休息交易日数、主分类和全部具体分类变化。当前不设置：

- 记忆有效期；
- 节点成员权重；
- 补涨或新题材得分；
- 自动买点。

11、12月分析完成后，再根据真实案例归纳哪些节点、哪些角色和哪些再激活类型具有稳定意义。

## 四、竞价数据缺口

摩恩电气案例说明，竞价封单增减会改变核心与同身位竞争者的优先级。当前历史涨停池没有竞价封单时间序列，也没有每次开板—回封的完整时间点。

竞价安全层位于 `data/research/auction/`。在可靠真相源出现前保持空文件：

```powershell
python tools/auction_observations.py validate
```

只允许实时快照或可重复核验的历史快照。用户事后口述属于训练纠错，不得伪装为历史竞价原始数据。

## 五、退出决策面的内容

以下内容可保留在原始数据中，但默认不进入紧凑研究视图：

- 最强风口排名；
- 进攻/防守模型与综合评分；
- 固定板数或固定换手阈值；
- 同花顺 `reason_type`；
- 根据封板时间自动判断主动性；
- 根据题材涨停数量自动判断带动性；
- 把一字指引永久映射为同身位竞争者。

市场环境、首板数量和题材时序仍保留为背景证据，但不能代替个股自身形态与动态竞争。
