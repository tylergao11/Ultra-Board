# 研究系统使用说明

## 数据与职责

- SQLite 正式库：`data/store/research.sqlite`。
- 原始下载资料：`data/`；每日开盘啦资料追加到 `data/kaipanla/raw/`。
- 静态、动态规则：`data/store/rules/static_rules.json`、`dynamic_rules.json`。
- 操作流程：`AGENTS.md`。程序实现集中在 `tools/`。
- 根目录研究总表、买卖表及 CSV 从数据库生成；当前导出位置由 `data/store/exports/current.json` 指定。
- 新总表发布成功后，旧导出文件自动删除，导出目录保留当前一批。

日常研究在本地完成。用户用自然语言指定范围和题材修正，agent 执行下面的入口。GitHub 交接方法单独维护在 [GitHub与多电脑使用](GitHub与多电脑使用.md)。

临时副本统一保存在 `data/store/tmp/`，由程序登记具体文件并在结束时逐项清理。中断遗留使用 `temp-clean` 重试，本地收尾也会自动执行。工具只清理登记的文件，遇到未登记内容会列出具体路径。

## 一批研究

准备用户指定数量、代码或日期范围的材料：

```powershell
python tools/research_cli.py batch-prepare --output data/research/<本批目录> --limit <数量> --year <年份> --offline
```

也可重复传入 `--record-key "代码|记录日期"`，或使用 `--from-date`、`--to-date`。`--offline` 复用本地资料并列出缺项。

准备阶段生成 `facts.json`、`brief.json` 和 `decisions.json`。读取精简材料后，只填写需要新判断的题材、依据和公告：
- main_theme：本轮唯一主炒。
- main_theme_basis：题材判断依据。
- announcement_pollution：公告污染 true 或 false。
- announcement_basis：公告判断依据。
- additional_evidence：补充来源，可留空。

已在库内的判断自动复用。共享高标题材缺项集中列在 high_themes，同一个启动轮只填写一次。补涨、压制、竞争清单与标准依据由程序生成。

提交：

```powershell
python tools/research_cli.py batch-commit --batch data/research/<本批目录>
```

提交将输入与派生结果一起保存，自动核对并生成总表。完成记录的草稿随即删除；部分完成时，材料只保留待办记录，已保存的输入从草稿清除。整批完成后留下 `batch.json`，其中仅有范围和记录键，供今后查询当前结果。

提交直接从数据库准备事实，`facts.json` 和 `brief.json` 随用随生成。材料损坏或清理中断时可重新准备；已完成批次重复提交会读取当前库，完成剩余刷新和清理。部分交易批次保留尚未完成的记录。

复核已完成批次：

```powershell
python tools/research_cli.py batch-verify --batch data/research/<本批目录>
```

核验直接读取当前库，检查结论、依据、逐日明细、竞争清单和总表。输入相同会跳过重复写入及导出。

## 修正一个题材

```powershell
python tools/research_cli.py theme-set --record-key "记录键" --theme "题材"
```

题材按“股票代码 + 实际首板日”保存。一次修改会重算该轮和相关候选的补涨、压制、竞争清单、依据与总表，失效清单自动清除。`--basis` 可补充依据，`--preview` 可查看影响而不保存研究输入。

## 批量输入与时点属性

```powershell
python tools/research_cli.py derive --input data/research/<输入文件>.json
```

输入包含：
- record_keys：可选的记录键范围。
- themes：每项包含 code、first_board_date，以及要修改的 main_theme；basis、sources 可补充。
- themes 中的 attributes：add、remove、from_date、to_date 表示该轮的时点例外，附 basis 和 sources。
- announcements：以记录键索引 pollution、basis、sources。

人工输入保存成功后删除提交文件，资料缺项列在结果中，相关记录显示“待补齐”。补齐资料后运行 derive 续算。文件删除失败时，重复执行会识别已保存的输入，保持期间的新修正。题材及例外保存在 SQLite；通用归并维护在静态规则的“自动匹配”字段。

按已完成批次重算并保存耗时：

```powershell
python tools/research_cli.py derive --batch data/research/<本批目录> --report data/research/<本批目录>/performance.json
```

不传范围的 derive 重算已接入自动推导的记录。口径变动或新增数据入库后使用此入口更新。返回取数、匹配、写入核对、导出和总耗时。

## 交易研究

默认研究静态题材，交易记录与收益保持原样。用户安排交易研究时，准备命令使用 `--scope both`；题材仍通过同一个自动推导入口保存。动态输入填写竞价、卡位、买卖点和结果，提交消费当前静态结论，分别核验交易字段。

## 查询与维护

```powershell
python tools/research_cli.py summary
python tools/research_cli.py rules
python tools/research_cli.py research --record-key "记录键"
python tools/research_cli.py stock --code <代码>
python tools/research_cli.py issues
python tools/research_cli.py impact --object <代码或证据路径>
```

行情、属性资料下载后增量入库：

```powershell
python tools/research_cli.py ingest --path <资料文件或目录>
python tools/research_cli.py derive
```

日常资料集中维护与本机滚动备份：

```powershell
python tools/research_cli.py maintain --keep-backups 3
```

维护报告位于 `data/store/maintenance/`。静态维护沿用交易统计，交易任务负责更新收益计算。

## 备份与恢复

```powershell
python tools/research_cli.py backup --output data/store/migrations/recovery/current
python tools/research_cli.py restore-drill --backup <备份文件.sqlite> --report <恢复核验报告.json>
```

恢复入口使用已核对的实际备份路径：

```powershell
python tools/research_cli.py restore --backup <备份文件.sqlite> --target data/store/research.sqlite --restore-files
```

写入中断会回滚本次数据库事务。导出中断会留下待刷新状态，重复执行即可完成展示更新。结构或恢复专项检查使用 `verify`；它读取当前库、核对原始记录归档与正式输出，报告保存在 `data/store/verification/current/verification.json`。日常研究使用本批核验。
