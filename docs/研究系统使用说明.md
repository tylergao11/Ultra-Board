# Ultra Board 统一研究系统使用说明

本系统以 `data/store/research.sqlite` 为唯一结构化研究库。`data/` 下的下载文件继续保存原始证据；根目录两张 JSON、CSV 和统计文件均由研究库生成，用于展示和交换。正式规则保存在独立规则文件中，研究始终读取当前内容，日常操作统一从 `tools/research_cli.py` 进入。

## 数据归属

| 位置 | 职责 |
| --- | --- |
| `data/kaipanla/`、`data/price_checks/`、`data/research/` | 原始下载、行情核验和迁移前研究证据；保留原路径与内容校验值 |
| `data/store/research.sqlite` | 股票、时点属性、行情事件、公告、启动轮、一字轮、首开事件、股票池、当前规则和当前研究结论 |
| `data/store/rules/static_rules.json`、`dynamic_rules.json` | 静态与动态规则的正式可编辑来源；研究始终读取当前内容 |
| `data/store/exports/` | 按数据库快照生成的精简 JSON、CSV、统计与批次清单 |
| `一字首开研究总表.json`、`一字首开买卖研究表.json` | 正式库生成的当前展示表；不作为规则或详细依据维护位置 |
| `data/store/migrations/` | 冻结基线、字段映射、核验报告和恢复点 |

旧记录继续使用 `底稿记录键` 查询。详细判断、逐项核验和来源通过 `research` 命令读取；公共资料在证据目录维护一份，由多条研究引用。

## 运行环境和命令格式

在 `D:\Ultra-Board` 运行，使用 Python 3。默认数据库为 `data/store/research.sqlite`：

```powershell
python tools/research_cli.py summary
```

迁移或隔离核验时，`--db` 必须放在子命令之前：

```powershell
python tools/research_cli.py --db <隔离数据库.sqlite> summary
```

所有项目文本和请求文件使用 UTF-8；交易日期使用 `YYYY-MM-DD`；时间按 Asia/Shanghai 解释并保留源资料精度。数据库中的价格以千分之一元整数保存，比例以百万分之一保存。NULL 表示源资料没有该值，显式 `false` 与空字符串在原文 JSON 中原样保存。

## 每批开始前读取规则

每批研究都先完整读取当前 `AGENTS.md` 的“每批复盘流程”和规则中心：

```powershell
Get-Content -LiteralPath AGENTS.md -Raw -Encoding UTF8
python tools/research_cli.py rules
```

`rules` 默认直接读取当前静态规则文件；交易任务使用 `rules --scope dynamic`，需要全部内容时使用 `rules --scope all`。每批读取一次对应口径。同一段连续工作中的跨电脑同步只在开始、结束时执行。

## 建库、迁移和新增证据

冻结或复核迁移基线：

```powershell
python tools/research_cli.py baseline --output data/store/migrations/baseline-20261112-initial
```

首次建库或专项修复时导入冻结源文件和现有数据。日常数据更新使用后文的 `ingest`：

```powershell
python tools/research_cli.py migrate
python tools/research_cli.py summary
```

新下载的响应先原样落到 `data/` 的既定目录，再登记内容校验值和路径：

```powershell
python tools/research_cli.py register-evidence --path data/research/<实际文件>.json
```

问财取数入口可在保存响应后同步登记证据：

```powershell
python tools/query_iwencai.py --questions-file <UTF-8问题文件.json> --output-dir <证据目录> --register-db
```

`register-evidence` 只登记证据。新增属性、板块成员、开盘啦每日资料和行情核验文件使用同一增量入口，支持重复的 `--path` 和目录：

```powershell
python tools/research_cli.py ingest --path data/kaipanla/concepts_current/<采集日>/<代码>.json
python tools/research_cli.py ingest --path data/kaipanla/raw/<交易日>
python tools/research_cli.py fetch-attributes --code <代码> --code <另一代码>
```

显式路径只校验指定文件；相同内容跳过。属性和板块成员按文件事务更新，开盘啦行情按交易日更新事实池，同时重建受影响的当日、下一交易日消息事实与断板池。已有启动轮和首开事件关联到的数据变化记入 `issues`，正式研究结论保留，由研究任务根据新事实处理。其他文件登记为原始证据。新建研究候选仍沿用现有研究记录入口，增量下载负责事实更新。

`fetch-attributes` 批量取开盘啦完整属性，保存原始响应后直接增量入库。当天已有响应直接复用；`--refresh` 保存独立的新响应，保留之前的原始文件。查询使用最晚日期、该日期最后取得的完整快照，历史适用性由当前研究口径裁决。失败按股票返回，其他股票继续。

批量盘点当前证据路径、区分当前文件、同路径旧文件和已清理路径时运行：

```powershell
python tools/research_cli.py refresh-evidence
```

`AGENTS.md`、`data/store/rules/static_rules.json` 或 `data/store/rules/dynamic_rules.json` 调整后，先保存来源，再单独同步规则中心：

```powershell
python tools/research_cli.py sync-rules
python tools/research_cli.py rules
```

该命令把规则文件的当前内容同步到研究库，旧内容自动留档，不重复导入行情和研究记录。

## 常用查询

## 每日开盘啦数据维护

每日下载程序把最新交易日资料追加到 `data/kaipanla/raw/` 及相关证据目录后，运行：

```powershell
python tools/research_cli.py maintain --keep-backups 3
```

该命令检查文件元数据，只对新增或变化的文件校验内容并增量入库，检查关联完整性，再按变化生成展示和轮换恢复点。报告保存在 `data/store/maintenance/<执行时间>/maintenance_report.json`。首次运行复用已有结构化数据建立增量登记；后续未变化文件直接跳过。下载程序知道输出路径时优先调用 `ingest --path`，直接处理本次范围。静态维护沿用既有交易统计，交易任务负责更新统计。每日恢复点保留最近三份。

维护后可用以下命令快速查看最新交易日的池；日期取维护报告中的 `latest_raw_trade_date`：

```powershell
python tools/research_cli.py pool --type high_standard --date <最新交易日>
python tools/research_cli.py pool --type strict_one_word --date <最新交易日>
```

### 查股票档案

```powershell
python tools/research_cli.py stock --code 002209
```

返回内部身份、名称历史、启动轮、首开事件和行情资料覆盖。

### 查时点属性

```powershell
python tools/research_cli.py attributes --code 002209 --date 2026-11-11
```

返回研究日当时可选的最近属性快照、原标签、统一名称、历史适用状态、板块成员关系和证据路径。若 `missing` 为 `true`，先补证据，不使用后续快照倒推历史。

### 查股票池

```powershell
python tools/research_cli.py pool --type high_standard --date 2026-11-11
python tools/research_cli.py pool --type strict_one_word --date 2026-11-11
python tools/research_cli.py pool --type first_open_candidate --date 2026-11-11
python tools/research_cli.py pool --type candidate_competitors --date 2025-03-07 --record-key "603700|2025-03-06"
```

池查询默认使用当前已导入数据，返回覆盖状态、成员身位、查询方向和证据。补涨、高位一字压制和首开日竞争分别查询，保持各自取数方向。需要查看指定旧数据批次时添加 `--input-batch <批次>`。

### 查完整研究和依据

```powershell
python tools/research_cli.py research --record-key "002209|2026-11-11" --plan formal
```

返回记录身份、当前静态结论、当前动态方案、检查明细、原文 JSON 和证据引用。正式方案使用 `formal`；对照方案按数据库中的实际 `plan_code` 查询。

### 查缺项和影响

```powershell
python tools/research_cli.py issues
python tools/research_cli.py issues --from-date 2026-01-01 --to-date 2026-12-31
python tools/research_cli.py impact --object 002209
python tools/research_cli.py impact --object data/kaipanla/raw/2026-11-11/zt_pool.json
```

`issues` 输出具体对象、缺项类型、严重度、影响范围和处理状态。`impact` 按股票代码、记录键、日期或证据路径反查关联的静态研究、动态研究、来源记录和缺项。原资料缺项继续保留；迁移、写入或发布新增的断链须先修复。

## 写入研究结论

日常指定范围复盘使用“准备材料、完成判断、提交结果”入口。下方单条 `write` 适合用户确认修订、指定记录修订和故障恢复。

写入请求使用 UTF-8 JSON 文件。每次提交提供唯一 `request_id`、记录键和研究类型；规则与当前记录由系统自动读取：

```json
{
  "request_id": "batch-14-002574-2025-03-12-static-v1",
  "record_key": "002574|2025-03-12",
  "kind": "static",
  "confirmation_status": "pending_user_confirmation",
  "updates": {
    "唯一主炒作属性": "以本批现行规则得出的实际值",
    "补涨判断": "以本批现行规则得出的实际值",
    "压制判断": "以本批现行规则得出的实际值",
    "压制依据": "逐个更高身位严格一字对象的实际核验依据",
    "公告污染": false,
    "映射依据": "实际依据",
    "公告污染依据": "实际依据"
  }
}
```

提交命令：

```powershell
python tools/research_cli.py write --input data/research/<批次>/research-write.json
```

写入采用 `BEGIN IMMEDIATE` 单写者事务，自动读取当前规则和当前结论并保存修订痕迹。同一 `request_id` 与同一内容重复提交时返回原结果，内容变化时使用新的请求号。

用户确认前，`confirmation_status` 保持 `pending_user_confirmation`。用户确认后按新的唯一请求提交确认修订；禁止在缺少确认来源时填成已确认。

## 生成展示表和统计

先生成独立批次：

```powershell
python tools/research_cli.py export
```

输出目录包含精简静态 JSON、精简动态 JSON、两份 UTF-8 BOM CSV、统计和 `manifest.json`。清单记录数据库快照、输入批次、当前规则来源、文件大小和 SHA-256。

核验通过后发布根目录展示表：

```powershell
python tools/research_cli.py export --publish-root
```

`data/store/exports/current.json` 指向当前完整批次。详细证据留在数据库和原始资料中，展示表保持精简。统计同时保留正式库计算、迁移前统计存档和假设对照，方案与分母分开呈现。

## 核验、备份和恢复

生成结构、规则与覆盖报告：

```powershell
python tools/research_cli.py reports --output data/store/migrations/reports
```

执行真实数据完整核验：

```powershell
python tools/research_cli.py verify --report-dir data/store/migrations/verification
```

这项完整核验用于数据结构、迁移逻辑和恢复流程调整，包含 SQLite 完整性、外键、旧键映射、迁移原文、当前结论、字段映射、重复业务身份、证据路径、事务回滚、重复导入、UTF-8 往返和代表性查询耗时。日常研究核对本次涉及记录。

建立当前恢复点：

```powershell
python tools/research_cli.py backup --output data/store/migrations/recovery/current
```

命令生成 SQLite 一致性副本、切换相关文件归档和 `restore_manifest.json`。使用清单中的实际数据库文件进行隔离恢复演练：

```powershell
python tools/research_cli.py restore-drill --backup data/store/migrations/recovery/current/<实际备份文件>.sqlite --report data/store/migrations/verification/restore_drill.json
```

正式恢复前停止写入，核对备份 SHA-256 和恢复演练结果，再执行：

```powershell
python tools/research_cli.py restore --backup data/store/migrations/recovery/current/<实际备份文件>.sqlite --target data/store/research.sqlite --restore-files
python tools/research_cli.py summary
python tools/research_cli.py verify --report-dir data/store/migrations/verification-after-restore
```

`restore-drill` 同时核验数据库 SHA-256、逻辑快照、ZIP 校验值、ZIP 条目清单和每个文件的校验值。`restore --restore-files` 先为当前项目文件建立 `pre-restore-files-*.zip`，再从匹配的切换包恢复规则源、脚本、项目说明和两张展示表；数据库替换前另保存同目录 `.pre-restore` 副本。恢复后的 `summary` 和 `verify` 通过后恢复日常写入。只恢复数据库时省略 `--restore-files`。

## 失败处理和发布回退

- 导入或写入失败：保留原始证据和错误输出，查询 `issues`；事务会回滚本次未完成写入。
- 当前结论已变化：查询最新 `research`，按当前口径整理后用新的 `request_id` 提交。
- 导出核验失败：保留上一版 `data/store/exports/current.json`，不执行 `--publish-root`。
- 发布后发现问题：停止写入，按当前恢复点执行 `restore`，随后重新生成展示表。
- 证据冲突：保存所有来源及采纳依据；当前正式结论保持原值，等待有依据的修订和用户确认。

## 日常每批复盘

研究数量或范围由用户当次指定。准备入口默认静态研究，自动补取缺失的个股属性：

```powershell
python tools/research_cli.py batch-prepare --limit <本次数量> --year <年份> --output data/research/<本批目录>
python tools/research_cli.py batch-prepare --record-key "<记录键>" --record-key "<另一记录键>" --output data/research/<本批目录>
python tools/research_cli.py batch-prepare --from-date <起日> --to-date <止日> --output data/research/<本批目录>
```

数量和日期范围选取范围内未研究记录，按日期排序；显式记录键用于指定股票或重写。缺项记录始终保留在未研究范围，进度游标仅作记录。生成：

- `brief.json`：优先读取的精简材料，共享证据按引用保存一次；含缺项及适用范围。按股票或共享证据读取，避免反复输出整份文件。
- `facts.json`：写回与核验使用的完整材料，含候选和高标首二、完整属性、实际一字日、公告及潜在竞争对象；疑点按对应部分读取。
- `decisions.json`：本次工作草稿，默认只有静态判断。正式结论以 SQLite 为准。

重复运行相同准备命令会更新事实并保留草稿；直接用 `batch-prepare --output <原目录>` 可继续原范围。`--offline` 使用本地资料并列明缺项。通过静态筛选后的竞争对象属性，在草稿写入筛选结论后再次准备时集中补齐。交易任务明确使用 `--scope both`，旧的静态与动态联合批次继续兼容。

执行顺序：

1. 重新读取 `AGENTS.md` 全部流程及当前规则。
2. 在 `decisions.json` 中完成指定范围的判断。缺资料的记录在该条顶层写 `defer_reason` 和具体原因，其他独立记录继续提交；补齐后移除该字段再提交。
3. 提交本批并自动生成展示表：

```powershell
python tools/research_cli.py batch-commit --facts data/research/<本批目录>/facts.json --decisions data/research/<本批目录>/decisions.json
```

4. 提交入口完成本次静态写入、核验和进度更新，输出写入、核验、导出分段耗时。交易记录保持原样，已有交易统计沿用并标明来源。相同提交直接复用，跳过重复导出。
5. 向用户报告本次结论及具体缺项，等待确认。指定重写时只准备并修改指定记录键。
6. 连续工作结束时运行 `tools/finish_work.ps1`，统一检查、备份和 GitHub 同步。整库验收用于结构调整、恢复与专项排查。

单独复查已完成批次时使用：

```powershell
python tools/research_cli.py batch-verify --facts data/research/<本批目录>/facts.json --decisions data/research/<本批目录>/decisions.json
```

口径直接维护当前规则文件，脚本参数和实现留在工具中。沿用用户对研究范围、口径调整和结论修正的授权；已确认结论保留，按用户指定范围修改。原始证据保持原地可追溯。
