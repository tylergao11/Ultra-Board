# 研究系统使用说明

## 数据与职责

- SQLite 正式库：`data/store/research.sqlite`。
- 原始下载资料：`data/`；每日开盘啦资料追加到 `data/kaipanla/raw/`。
- 静态、动态规则：`data/store/rules/static_rules.json`、`dynamic_rules.json`。
- 操作流程：`AGENTS.md`。程序实现集中在 `tools/`。
- 根目录研究总表、买卖表及 CSV 从数据库生成；当前导出位置由 `data/store/exports/current.json` 指定。
- 新总表发布成功后，旧导出文件自动删除，导出目录保留当前一批。

日常研究在本地完成。用户用自然语言指定范围和题材修正，agent 执行下面的入口。GitHub 交接方法单独维护在 [GitHub与多电脑使用](GitHub与多电脑使用.md)。

临时副本统一保存在 `data/store/tmp/`，由程序登记具体文件并在结束时逐项清理。中断遗留使用 `temp-clean` 重试，本地收尾也会自动执行。工具只清理登记的文件，遇到未登记内容会列出具体路径。

## 一批研究

准备用户指定数量、代码或日期范围的材料：

```powershell
python tools/research_cli.py batch-prepare --output data/research/<本批目录> --limit <数量> --year <年份>
```

也可重复传入 `--record-key "代码|记录日期"`，或使用 `--from-date`、`--to-date`。`--offline` 复用本地资料并列出缺项。

准备阶段生成 `facts.json`、`brief.json` 和 `decisions.json`。读取精简材料后，只填写需要新判断的题材、依据和公告：
- main_theme：本轮唯一主炒。
- main_theme_basis：题材判断依据。
- announcement_pollution：公告污染 true 或 false。
- announcement_basis：公告判断依据。
- additional_evidence：补充来源，可留空。

已在库内的判断自动复用。共享高标题材缺项集中列在 high_themes，同一个启动轮只填写一次。补涨、压制、竞争清单与标准依据由程序生成。

提交：

```powershell
python tools/research_cli.py batch-commit --batch data/research/<本批目录>
```

提交将输入与派生结果一起保存，自动核对并生成总表。完成记录的草稿随即删除；部分完成时，材料只保留待办记录，已保存的输入从草稿清除。整批完成后留下 `batch.json`，其中仅有范围和记录键，供今后查询当前结果。

提交直接从数据库准备事实，`facts.json` 和 `brief.json` 随用随生成。材料损坏或清理中断时可重新准备；已完成批次重复提交会读取当前库，完成剩余刷新和清理。部分交易批次保留尚未完成的记录。

复核已完成批次：

```powershell
python tools/research_cli.py batch-verify --batch data/research/<本批目录>
```

核验直接读取当前库，检查结论、依据、逐日明细、竞争清单和总表。输入相同会跳过重复写入及导出。

## 出生当日补涨题材清单

总表的“补涨题材日期”使用实际首板日；“出生当日补涨题材”列全当天合格高标的唯一主炒，按当前规则归并并去重。包含当天达到门槛的晋级高标和合格当日断板高标，不与候选自身属性取交集，不因已命中一个方向而截断。空数组表示当天没有合格高标；题材尚未确认时整段不提交，不能当成空数组。

新批次提交和题材重算自动生成该字段。已有研究按关注日期选择范围补填，保留原有主炒、补涨、压制、公告和交易结论：

```powershell
python tools/research_cli.py birth-themes --from-date 2025-01-01 --to-date 2025-08-31
python tools/research_cli.py birth-themes --from-date 2026-01-01 --to-date 2026-12-31
```

加 `--preview` 只预检。共享高标需要补核时，使用 `--input` 传入只含 `themes` 的正式人工输入，字段与 `derive` 相同；成功提交后删除输入草稿。数据库同时保留“出生当日补涨高标”逐票来源，JSON与CSV从同一正式结果生成。历史范围口径变化后用同一入口刷新，不手工维护清单。

加 `--audit` 单独只读审计：直接对照出生当日及前一交易日原始涨停池，检查高标全集、题材去重、首板日期、JSON/CSV一致性和数据库完整性。该模式不与预检或人工输入混用。

## 修正一个题材

```powershell
python tools/research_cli.py theme-set --record-key "记录键" --theme "题材"
```

题材按“股票代码 + 实际首板日”保存。一次修改会重算该轮和相关候选的补涨、压制、竞争清单、依据与总表，失效清单自动清除。`--basis` 可补充依据，`--preview` 可查看影响而不保存研究输入。

## 批量输入与时点属性

```powershell
python tools/research_cli.py derive --input data/research/<输入文件>.json
```

输入包含：
- record_keys：可选的记录键范围。
- themes：每项包含 code、first_board_date，以及要修改的 main_theme；basis、sources 可补充。
- themes 中的 attributes：add、remove、from_date、to_date 表示该轮的时点例外，附 basis 和 sources。
- announcements：以记录键索引 pollution、basis、sources。

人工输入保存成功后删除提交文件。需要人工判断的共享题材由静态研究 agent 完成；行情缺失调用统一取数入口自动补取，失败反馈给执行 agent 处理。文件删除失败时，重复执行会识别已保存的输入，保持期间的新修正。题材及例外保存在 SQLite；通用归并维护在静态规则的“自动匹配”字段。

按已完成批次重算并保存耗时：

```powershell
python tools/research_cli.py derive --batch data/research/<本批目录> --report data/research/<本批目录>/performance.json
```

不传范围的 derive 重算已接入自动推导的记录。口径变动或新增数据入库后使用此入口更新。返回取数、匹配、写入核对、导出和总耗时。

## 交易研究

默认研究静态题材，交易记录与收益保持原样。用户安排交易研究时，准备命令使用 `--scope dynamic`；只填写竞价、卡位、买卖点和结果。提交只读取总表已经保存的静态结论，交易 agent 独立写入买卖表，不触发静态推导。

## 查询与维护

```powershell
python tools/research_cli.py summary
python tools/research_cli.py rules
python tools/research_cli.py research --record-key "记录键"
python tools/research_cli.py stock --code <代码>
python tools/research_cli.py issues
python tools/research_cli.py impact --object <代码或证据路径>
```

行情、属性资料下载后增量入库：

```powershell
python tools/research_cli.py ingest --path <资料文件或目录>
python tools/research_cli.py derive
```

日常资料集中维护：

```powershell
python tools/research_cli.py maintain
```

维护报告只保留 `data/store/maintenance/current/maintenance_report.json`。每次发布从当前有效交易记录汇总统计；交易任务负责逐笔交易判断和收益计算。动态口径变更后，废弃交易结论直接删除，按现行口径复核后重新生成；原始证据和仍有效的已确认结论保留。日常维护默认不生成备份，用户明确需要时通过备份入口执行。

## 备份与恢复

```powershell
python tools/research_cli.py backup --output data/store/recovery/current
python tools/research_cli.py restore-drill --backup <备份文件.sqlite> --report <恢复核验报告.json>
```

恢复入口使用已核对的实际备份路径：

```powershell
python tools/research_cli.py restore --backup <备份文件.sqlite> --target data/store/research.sqlite --restore-files
```

写入中断会回滚本次数据库事务。导出中断会留下待刷新状态，重复执行即可完成展示更新。结构或恢复专项检查使用 `verify`；它核对当前库、证据引用和正式输出，报告保存在 `data/store/verification/current/verification.json`。日常研究使用本批核验。

## 复用交易事实

每批静态判断提交后，自动补齐候选与已列明竞争者的年度日K；按候选与竞争者的实际所需日期检查日K，已覆盖日期直接复用。确认停牌的日期保留公告依据，不填造价格。同花顺缺项时复用本地新浪数据，仍缺时从行情接口补取。只处理研究中实际使用的股票。交易准备时自动填入首开日、前一日和后续日K，行情字段无需人工填写。

```powershell
python tools/research_cli.py market-ensure --from-date 2025-01-01 --to-date 2025-05-31
python tools/research_cli.py market-ensure --from-date 2026-01-01 --to-date 2026-12-31
python tools/research_cli.py trade-facts --record-key <底稿记录键> --days 20
```

跨年交易准备可使用 `market-ensure --from-date 2025-01-01 --to-date 2026-12-31 --days 20`，检查首开前一日和随后20个市场交易日。此窗口只用于行情准备，不代表已计算卖点或保证未来20日均已发生。覆盖检查认可已通过身份及价格校验的同花顺、新浪、开盘啦历史盘口和问财日行情。

停牌事实保存至 `data/market_status/*.json`，结构为 `{"kind":"reviewed_suspensions","records":[{"code":"六位代码","dates":["YYYY-MM-DD"],"basis":"公告核验依据","sources":["本地公告路径"]}]}`，通过 `ingest --path <文件>` 入库。必须先核对公告覆盖日期；入口检查证据存在、日期格式和已有日线冲突，停牌只保存为事实，不补造价格。停牌原文保留在证据目录，不把个股事实写入工具。

`trade-facts` 支持重复传入记录键，自动准备候选与已列明竞争者的日K、涨跌停价和分钟分时。读取行情不会产生买卖判断，也不会改写研究表。交易 agent 读取当前交易口径独立判断；取数错误、价格冲突和事件时间精度随资料返回。

精确获取股票指定日期的日行情、涨跌停价和分钟分时，直接填代码、日期：

```powershell
python tools/research_cli.py market-fetch --code <六位股票代码> --date <YYYY-MM-DD>
```

需要同花顺封板时间明细时加 `--details`，此项在线请求需要 Node.js。接口按代码和日期核验，分钟分时与封板明细均保存原始响应；`facts.complete` 标出明细是否完整，与日K矛盾的时间明细保留具体事实交给交易 agent 判断。

问财明细请求使用直连，避免本机系统代理返回403；其余数据源仍使用原有连接方式。每次重试重新生成签名，成功缓存继续复用。

`--code`、`--date` 可分别重复传入；脚本对代码与日期组合去重，最多4个请求并行。接口地址、历史请求头、代码与日期校验均固定在采集模块。已有有效资料直接复用，`--refresh` 强制重新获取。请求失败后固定等3秒，最多重试3次；仍失败返回代码、日期、接口和具体错误给当前 agent，命令返回非零状态。成功项立即入库，错误响应不作为有效缓存。结果分别报告请求、重试等待和入库耗时。分钟分时与毫秒封板明细保留各自精度。

## 两项任务独立执行

- 静态 agent：`batch-prepare`、`batch-commit`、`theme-set`、`derive`，只负责总表研究。
- 交易 agent：`trade-facts` 取资料，`batch-prepare --scope dynamic` 与 `batch-commit` 提交交易研究；静态结论只读。
- `market-fetch`、`market-ensure` 只保存行情事实。发布、维护与本地收尾不调用行情网络接口，不计算交易结论。统计只汇总交易 agent 已写入的当前记录。
- 静态依赖实际改变时，清除受影响的旧交易判断，由交易 agent 重新研究；修改文字依据不会清除有效交易结论。
