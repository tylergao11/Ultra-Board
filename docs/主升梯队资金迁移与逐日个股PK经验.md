# 第一阶段统一梯队算法

当前只解决节点日收盘后的**梯队选择与模型定位**。个股买谁、是否买得到、次日竞价和成功率属于第二阶段，不得倒灌第一阶段。

## 一、信息边界

- 输入日期为节点日 `T`。
- 只读取 `T` 及以前的原始涨停池和 `information_cutoff=T` 的派生快照。
- 禁止读取 `T+1` 竞价、盘中结果、后续高度、收益和人工答案。
- 人工标签只允许由显式回测命令读取，普通选层入口永不访问隔离区。
- 个股题材只取当前连续连板路径上逐日真实出现过的开盘啦 `theme`。
- 禁止从 `concepts`、主营、静态概念堆、后来新闻或地域关系补题材；地域暂不参与。

安全入口：

```bash
python -m ultraboard.kaipanla.ladder_evidence node 2026-06-01
python -m ultraboard.review.ladder_selector select 2026-06-01
```

## 二、公告起源

公告只认三类：

1. 并购重组
2. 实控人变更
3. 股权转让

举牌、季报或年报增长、ST 摘帽、订单、再融资都按自然属性处理。

公告身份按事件起源判断：连续连板段的第一板一旦属于三类公告，后续即使每日主属性切换，整段仍保持公告起源。公告票不从市场结构中删除，但不能作为自然候选，也不计入自然题材发酵：

- 公告真一字：角色为“量能”，可帮助同层形成合富结构。
- 公告换手板：只保留为梯队结构，不进入第二阶段候选池。
- 源数据漏标只能写入 `data/kaipanla/announcement_overrides.json`；禁止在算法中按股票名或节点日期特判。

## 三、涨停原因发酵榜

神剑的市场排名真相源是开盘啦节点日“涨停原因”发酵榜原始顺序。历史数据由同日 `sector_ladder.json` 保存；该顺序的前二已与实时涨停原因接口逐项核对一致。必须保留接口原始位置，不按数量重排，不因剔除公告题材而让第三名递补成第二名。

首板数量仅作解释材料，不参与排名。

## 四、统一决策

### 1. 最高自然梯队

先保留全部二板及以上股票及其角色，再剔除公告起源票，得到最高自然板 `H`。神剑只能在 `H` 判断，禁止因为中位梯队题材更强而向下搜索神剑。

### 2. 神剑进攻

若 `H` 层至少一只自然票的沿途题材满足以下条件，则 `H` 命中神剑：

- 该题材位于节点日涨停原因发酵榜原始前二；
- 命中关系来自该股票当前连续连板路径上真实出现过的 `theme`。

等价判定：`H 层自然票沿途 theme 集合 ∩ 节点日涨停原因榜前二 ≠ ∅`。第三名无论数量多接近都不触发神剑。

题材触发只决定梯队，不保证触发该题材的股票最终胜出；第二阶段仍需在已冻结的 `H` 层内重新选票。

### 3. 合富防守

真一字必须满足开盘、最高、最低和收盘均为涨停价。T 字、高开秒封和开板回封均不算一字。

一个梯队形成合富的必要结构：

- 至少一只真一字锚；
- 同层至少一只自然票。公告一字可以只作量能，自然票负责候选资格。

自然低位一字若与更高自然票共享沿途题材，则受到高一身位压制，不能用它把目标层向下拉。公告一字只承担量能，不按题材压制。

选择顺序：

1. 最高自然层自身若形成有效合富，优先保留最高层；
2. 否则在更低层中，选择最低的、未被高层同题材压制的有效一字梯队。

### 4. 攻防重叠时的模型名

若最高自然层同时满足神剑与合富：

- 一字锚旁还有同层自然换手票，归为合富；
- 只有单只一字高标而无同层自然换手承接，仍归为神剑。

模型名用于描述资金结构，不改变已经选定的梯队。

### 5. 两者都不成立

神剑和合富均不成立时，默认选择二板，模型记为“无”。这不是无目标，而是跳过中位梯队，落到最低可选梯队；若市场客观上没有二板，才输出无目标。

## 五、脚本与 AI 的边界

第一阶段脚本固定输出：

- 目标梯队；
- 神剑／合富／无；
- 最高自然板；
- 涨停原因发酵榜前二；
- 一字锚、公告量能、自然候选和压制证据；
- `information_cutoff=T`。

第二阶段 AI 只能在脚本已选梯队内判断核心、补涨、风险和放弃，不得跨层推翻脚本。未来统计必须拆成“梯队命中率”和“梯队内选票命中率”。

## 六、第二阶段节点日竞价预期分

冻结梯队后，可在仍然只读取节点日 `T` 的前提下生成层内自然票次日竞价预期分 `E`：

```bash
python -m ultraboard.review.candidate_initial_score 2025-12-24
```

个股自身证据由五项等权组成：

1. 梯队模型与身位：20%；
2. 市场题材地位：20%，涨停原因榜原始位置占该项 80%，报告数量只占 20%，不得据数量重排；
3. 个股在评分题材内的身位与核心性：20%；
4. 首封主动性：20%，由绝对首封时刻和同题材自然队友相对次序组成；
5. 首封后传播：20%，统计此后才首次封板的同题材自然队友比例与数量。

日内主动性与传播合计 40%。公告票从自然队友时序中剔除，只单列量能。一字形态本身直接权重为 0：早封只能取得主动性证据，若没有市场题材地位、个股核心地位和此后传播，不能仅凭一字推导次日仍应一字。

个股沿途每个真实 `theme` 必须分别形成一套完整评分论点，再选其中总分最高的一套；禁止拿题材 A 的市场排名、题材 B 的核心地位和题材 C 的传播拼成一个虚假高分。若命中来自沿途旧 `theme` 而非节点日当前主 `theme`，仍保留该关系，但不能获得当前板块核心满分。

原始池只有首封时间，没有末封时间、开板次数和候选首封瞬间仍封住的队友数量。因此“前／同秒／后”只代表首次触板顺序，不代表当时封板状态，更不宣称候选因果带动了后续股票。

当前分值 `E` 表示节点日证据要求次日 09:25 给出多强的竞价，不是次日连板概率。次日实际竞价必须转换到同一刻度 `A`，超预期差为 `Δ=A-E`。后验结果只允许在显式校准入口中用于整体调权；禁止按单日结果改权重或写股票／日期特判。

同梯队 PK 的边界是第一阶段已经冻结的**全部自然票**，不要求题材相同，公告量能票不参与。先用个股自身证据分做两两强弱映射，再取对其余票的平均值作为预期 PK；分差 10 分约映射为 73／27，分差 20 分约为 88／12。多票梯队当前按“自身证据 90% + 预期 PK 10%”形成最终 `E`。如果梯队只有一只自然票，则 `pk_available=false`，不填中性 50 分，PK 实际权重归零，其余证据自动占满。

## 七、实际竞价与超预期差

显式后验入口：

```bash
python -m ultraboard.review.auction_score review 2025-12-22 --fetch-missing
python -m ultraboard.review.auction_score backtest \
  --labels .blind-test-quarantine/labels/stage1_locked.json \
  --fetch-missing
```

V2 把 T+1 集合竞价形成的开盘涨幅除以该股涨停幅度，再映射成自身开盘强度证据：平开为 50，涨停开为 100，跌停开为 0。多票梯队用同一映射比较全部自然候选，形成实际 PK，并按“开盘强度 90% + 实际 PK 10%”得到最终 `A`；同时单列 `PKΔ=实际PK-预期PK`，观察竞价时层内地位是否超预期。单票梯队仍由开盘强度占满。若多票梯队缺任一候选的 09:25 数据，则最终 `A` 与 `Δ` 明确缺失，不用降级公式制造不同刻度。历史库没有可靠的竞价成交额和 09:20～09:25 委托队列，因此竞价量、委托轨迹和全市场竞价一字结构均不补默认值，其中竞价一字因子按当前约定权重为 0。

超预期分组暂按 `Δ` 划分：

- `Δ≥15`：大幅超预期；
- `7≤Δ<15`：超预期；
- `-7<Δ<7`：符合预期；
- `-15<Δ≤-7`：不及预期；
- `Δ≤-15`：大幅不及预期。

收盘是否晋级独立放在 `after_close_outcome`，只用于后验校准，绝不参与 `E`、`A` 或 `Δ`。当前 31 个人工冻结训练节点、100 个候选采用 10% PK 权重后，`E` 与 `A` 相关系数为 0.3772，MAE 为 18.70；这里的 31 仅是已人工确认样本数，不是全历史算法节点总数。大幅超预期组晋级 16/20，超预期组 9/15。把绝对竞价与预期差交叉后，`A≥80 且 Δ≥7` 晋级 21/24，而 `A<80 且 Δ≥7` 为 4/11，仍说明超预期必须同时受实际竞价强度门槛约束。

PK 不是凭感觉加入：20 个多票节点中，实际竞价层内第一晋级 16/20，其余候选晋级 21/69；节点日预期层内第一晋级 13/20，说明相对强弱确有信息。但 0／10／20／30% 权重对照中，相关系数依次为 0.3618／0.3772／0.3888／0.3971，MAE 同时由 18.60 升至 18.70／19.09／19.51，且晋级与失败组的绝对 A 差随权重增大而略降。因此先用 10% 小权重保留 PK 信息，不把相关系数的机械上升误判成更强的连板预测；个股自身五项仍保持内部等权，后续只按新增跨样本证据小步调整。

## 八、回测边界

```bash
python -m ultraboard.review.ladder_selector backtest \
  --labels .blind-test-quarantine/labels/stage1_locked.json
```

这里统计的是与人工冻结标签的一致率，不是次日成功率。标签和算法输出必须分开保存；回测不允许让标签参与特征计算，也禁止为了单一日期写特判。

最终归纳：**神剑进攻，合富防守；皆无则二板。**
