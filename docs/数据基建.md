# 数据基建

## 一、唯一正式来源

Ultra-Board 的正式市场事实只读取开盘啦，唯一 canonical 路径是：

```text
data/kaipanla/raw/YYYY-MM-DD/
```

同花顺历史文件和既有研究产物可以继续保留作旧证据，但不得进入正式更新、单日事实组装、覆盖判断或字段兜底。来源没有提供的事实保持不可得，不用默认值、人工故事或另一供应商补造。

## 二、日快照

| 文件 | 内容 | 边界 |
|---|---|---|
| `sentiment.json` | 涨跌家数、涨跌停、市场情绪 | 保存开盘啦原始响应 |
| `expression.json` | 梯队情绪表达 | 不自动解释为周期结论 |
| `zt_pool.json` | 目标市场涨停池 | 排除ST与北交所，源行逐条对账 |
| `sector_ladder.json` | 题材梯队与反包信息 | 保留来源顺序，不当作强弱排名 |
| `_DONE` | 单日合同闭合 | 正式读取的必要条件 |
| `_MISMATCH` | 单日合同未闭合 | 存在时禁止正式读取 |

## 三、个股事实合同

`zt_pool.json/stocks[]` 当前正式读取：

- `code`、`name`；
- `boards`：开盘啦原始数组下标15的真实连板数；
- `boards_desc`：如“7连板”“3天2板”的来源描述；
- `theme`：开盘啦当日主分类，也是正式历史题材归属；来源为空时保留 `null`；
- `sector_code`：来源可能为空，保持 `null`，不反推或补造；
- `first_limit_ts`；
- `turnover_rate`、`amount`、`price`、`limit_pct`；
- 历史 `DailyLimitPerformance` 原始数组下标13提供流通市值；正式读取接口将其解释为 `circulating_market_cap` 并保留字段来源。该数值与成交额/换手率反推量级逐股闭合；当日 `GetPlateInfo_w38` 行结构不同，不套用这个下标；
- `is_fanbao`。

`theme_tags_text`/原始数组下标12仍按源保存，但不进入正式历史事实。开盘啦
历史接口会把后来出现的概念标签回填到旧日期，例如2024年记录可出现后来才
形成的概念；它只能用于原始响应溯源，不能用于当日题材筛选、扩散判断或回测。

`PidType 1~4` 必须与真实连板数相等；`PidType 5` 表示五板及以上，真实高度仍只认个股字段。反包只打标记，不抬高连续板数。

当前来源没有闭合提供以下事实，因此正式输出不出现这些字段：最终封板时间、开板次数、板型、真一字、总市值、封单金额与数量、逐股故事和日级复盘故事。

## 四、题材合同

个股历史归属只认同日 `theme`，题材梯队只认同日 `sector_ladder.json`。主分类缺失的股票仍保留在完整涨停池中，但不参加题材筛选。附加概念标签没有可靠的历史时间切片，因此不提供候选归属。

分类是供应商事实，不是交易结论。数据层不得从名称、新闻或历史故事自动推导题材，也不得输出龙头、补涨、切换、主动性、抗压性、带动性、评分或买点。

### 研究时如何核对个股完整属性

开盘啦的当日主分类、涨停原因、卡片附加标签和个股完整板块关系不是同一层信息：

- `theme` 与当前榜市场方向表示当天涨停被归入哪个主要方向；
- `plate_info.json` 的原因标题与正文只在快照日期确属当日时用于解释当天涨停故事；
- 当前榜股票行中的少量附加标签会随日期变化，只能作为完整属性的发现线索，不是稳定或穷尽的属性集合；
- `GetFeaturedSection` 返回个股当前完整板块关系及各板块当下表现，只能发现待核对关系，不能证明该关系在更早日期已经存在；
- `ZhiShuStockList_W8` 使用明确 `Date + PlateID` 查询某日板块成分，响应 `Day` 必须与查询日一致，查询日还必须不早于响应 `MinDay`；早于 `MinDay` 时即使接口返回 `Count=0`，也只表示历史不可得，禁止保存成零成员快照。当前已用澳洋健康的脑机接口关系验证其具备日期变化：合作出现以前的日期切片不含该股，之后才出现。因此它可以用于复核某个明确属性在研究日是否已经存在；
- `GetDayBaseFaceListZDEvnArt` 与 `SonPlate_Info` 用于核对对应日期的板块强度、涨停数、爆发原因和子方向表现。个股属于板块成分只证明连接存在，不能单独证明该资金池当天正在交易它。

这些接口没有混入 `load_day` 的正式日快照合同。历史板块成分另存到 `data/kaipanla/research_attributes/YYYY-MM-DD/PLATE_CODE.json`：请求一次取足成员，并要求实际成员数与响应 `Count` 完全一致；不足即失败，不接受“请求成功但只取前500只”。

历史板块成分只负责保留可复核事实，不生成固定回放、候选、角色或交易决定。研究者如何理解这些事实，不属于数据层合同。

## 五、市场摘要

市场摘要由同日开盘啦事实即时生成：

- 正式涨停股票数；
- 首板、高板、最高板与板数分布；
- 涨跌家数；
- 涨停、自然涨停、跌停、自然跌停参考；
- 市场情绪与梯队表达原始信息。

统计不能覆盖源数据。若跨接口范围不同，必须保留各自字段名和口径说明，不强行把数字修成一致。

## 六、读取接口

- `ultraboard.kaipanla.load_day`：唯一单日来源读取接口；
- `ultraboard.day_facts.build_day_component`：完整内部单日组件；
- `ultraboard.day_facts.build_day_facts`：公开只读事实视图；
- `python tools/market_day.py YYYY-MM-DD`：命令行查询；
- `python tools/market_memory.py ...`：跨日路径与梯队事实查询。

所有读取必须显式携带交易日或 `information_cutoff`，不能读取未来日期再回写旧判断。

## 七、更新与编码

正式更新只通过 `npm run data:update`，单日和区间参数见 [每日数据更新契约](每日数据更新契约.md)。JSON与Markdown统一使用UTF-8无BOM；写入必须先落临时文件再原子替换，完成标记最后提交。
