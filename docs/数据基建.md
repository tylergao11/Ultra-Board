# Ultra-Board 数据基建

当前阶段只保留三个互不越界的数据源。节点、进攻/防守模型及其派生输出已删除，后续从零建立。

覆盖审计入口：

```powershell
python tools/data_foundation.py --start 2025-10-09 --end 2025-12-31
```

该入口只报告各日期的数据是否存在，并同时给出知识总结、盲测决策和竞价快照数量。
缺少故事表示“尚未生成或录入”，不能解释为当天没有市场故事。

## 一、来源职责

| 数据 | 唯一来源 | 边界 |
|---|---|---|
| 个股主分类 | 开盘啦 `zt_pool.json/stocks[].theme` | 不接受同花顺或人工覆盖 |
| 个股全部具体分类 | 开盘啦 `stocks[].raw[12]`，读取时规范为 `stocks[].themes` | 只拆源字段，不做语义映射 |
| 题材梯队原文 | 开盘啦 `sector_ladder.json` | 源顺序不是交易结论 |
| 日级市场叙事 | 同花顺故事 v1 长图或 v2 官方复盘页 | 只作供应商收盘复盘归因 |
| 逐股市场故事 | v1 长图个股行或 v2 涨停池 `reason_type` 原文 | 保持原文，不拆分为题材 |
| 股价、市值与板上过程 | 同花顺 `limit_pool` | 提供股价、流通/总市值、换手率、封单、身位及封板过程 |
| 情绪与表达快照 | 开盘啦 `sentiment.json`、`expression.json` | 保留原文，不在源层解释 |

## 二、开盘啦分类合同

日目录：

```text
data/kaipanla/raw/YYYY-MM-DD/
  zt_pool.json
  sector_ladder.json
  sentiment.json
  expression.json
  plate_info.json  # 可选
  _DONE
```

`zt_pool.json` 的每只股票必须保留：

- `theme`：开盘啦主分类，来自原始数组下标 5。
- `theme_tags_text`：开盘啦全部具体分类原文，来自原始数组下标 12。
- `sector_code`：开盘啦分类代码，来自原始数组下标 19。
- `raw`：完整原始数组，用于来源审计。

统一读入口为 `ultraboard.kaipanla.load_day()`；它只拆分开盘啦原文并生成 `themes`，不引入关键词表或第二分类源。

动态归因时，`theme` 作为默认主归属，`themes` 作为候选集合。市场故事与资金时序可以把某个候选调整为当日交易主属性，但不得回写或覆盖开盘啦原始字段。`tools/extract_attribution_evidence.py` 只负责整理候选属性、板上行为和上午/下午后继序列，不负责评分或自动归因。

## 三、同花顺故事合同

`data/ths/stories/` 支持两个闭合来源合同。历史 v1 继续读取 `data/ths/strong_wind_images/` 中人工核对的“最强风口”长图；新增日默认由官方历史复盘页与涨停池 `reason_type` 生成 v2。

```json
{
  "date": "2026-08-06",
  "source": "tonghuashun_strong_wind_headlines",
  "source_image": "data/ths/strong_wind_images/2026-08/20260806.png",
  "stories": [
    {
      "source_position": 1,
      "story": "市场并购重组持续活跃；龙头十连板",
      "context": "并购重组",
      "headline": "并购重组：市场并购重组持续活跃；龙头十连板"
    }
  ]
}
```

v2 把日级 `market_story` 与平铺 `stock_stories` 分开，避免把全部股票挂在同一个市场看点下。`block_1890/1891`、`context`、原图顺序和 `reason_type` 都不能成为具体题材分类或风口排名。逐股故事完整覆盖是正式导出的必要条件。

## 四、同花顺涨停池合同

`data/ths/limit_pool/YYYY-MM-DD.json` 只负责：

- 股价、涨幅、流通市值与可用时的总市值；
- 换手率、封单金额、封单数量与封单/流通市值比；
- 当前连续板数 `boards`；
- 同花顺窗口描述 `boards_desc`；
- 首封、终封和炸板次数；
- 板型与真一字；
- 连板倒推的客观日期证据。

涨停池事实投影不携带 `reason_type`；故事采集器可以从同一官方端点独立读取其原文。两者都不得使用 `reason_type` 读取或生成题材，也不得生成节点、进攻/防守结论。

## 五、数据流

```text
开盘啦接口 -> 个股全部具体分类 + 题材梯队 + 情绪原文
同花顺长图或官方复盘页 -> 日级市场叙事
同花顺长图个股行或 reason_type -> 逐股市场故事
同花顺涨停池 -> 连板与封板过程事实

三层事实 -> 等待后续重新定义核心跃迁与买点模型
```

任何未来盲测都必须冻结到指定 `information_cutoff`，不得读取 `.blind-test-quarantine/` 或用后续结果解释当时判断。
