# Ultra-Board 数据基建

> 当前合同：题材、连板高度与封板过程全部只认同花顺，系统不存在第二真相源。

## 一、真相源

| 数据 | 唯一来源 | 允许用途 |
|---|---|---|
| 当天主分组 | `data/ths/strong_wind/YYYY-MM-DD.json` | 个股题材身份 |
| 风口原位次 | 同上股票的 `theme_rank`；旧文件无该字段时才等于 `groups[].rank` | 进攻模型前二风口 |
| 公告身份 | 同上明确公告分组，或“其他概念”人工审核后的“公告题材” | 排除公告高度、节点日与选层 |
| 原图证据 | 同上 `source_image` 指向的同花顺官方长图 | 人工复核 |
| 当前连续板数 | `data/ths/limit_pool/YYYY-MM-DD.json` 的 `boards` | 纯客观梯队高度 |
| 同花顺窗口描述 | 同上 `boards_desc`、`limit_up_window_days`、`limit_up_total` | 展示 `N天M板`，不得代替当前连续板数 |
| 真一字 | 同上 `one_price`，由同花顺板型与封板过程闭合校验 | 防守模型一字锚 |
| 首封、终封、炸板次数 | 同上 `first_limit_ts`、`final_limit_ts`、`open_count` | 过程核对，不改变题材 |

### 当前连续板数合同

1. `首板` 与 `N天N板` 是无歧义描述，可直接确定当前连续板数。
2. `N天M板` 且 `N>M` 时，`M` 只是窗口内涨停总数上限，不能直接作为当前板高。
3. 歧义窗口从当天开始，沿同花顺个股 K 线中的实际交易日向前遍历；前一实际交易日在同花顺涨停池出现则加一，不出现即停止。停牌日不属于该股交易日，不得打断连板。
4. 每个倒推结果保存 `consecutive_limit_up_dates`；窗口总数只参与上限与一致性校验。
5. `high_days` 为空时必须走完整倒推并保留来源，禁止默认首板。

## 二、同花顺逐日结构

```json
{
  "date": "2026-08-06",
  "source": "tonghuashun_strong_wind",
  "source_image": "data/ths/strong_wind_images/2026-08/20260806.png",
  "groups": [
    {
      "rank": 1,
      "title": "并购重组",
      "stocks": [
        {
          "code": "603221",
          "name": "爱丽家居",
          "theme_rank": 1,
          "poster_rank": 1,
          "poster_group": "并购重组",
          "theme_assignment": "explicit_group"
        }
      ]
    }
  ],
  "issues": []
}
```

读侧硬门禁：

1. `date`、`source`、`source_image` 必须有效，原图必须存在。
2. `rank` 只表示重排后的展示顺序，必须从 1 连续递增；股票代码、名称必填，同日只能有一个主归属。
3. `issues` 必须为空。
4. 最终数据不得残留“其他”“其他概念”“其它概念”或“未分类”。
5. 当天客观涨停股必须全部能在同花顺主分组中找到。

## 三、人工审核

OCR 只负责还原图片和列出兜底分组的事件原文。对“其他概念”必须逐图、逐股找真实封板驱动：

- 独立公司事件驱动，如拟收购、资产注入或并购预期、控制权变更、业绩预增等，统一填写“公告题材”。
- 随当天行业或概念板块联动，填写真实自然题材。
- 不能只看字面。拿不准时结合当天热点、同板块涨停、封板时间与跟随关系人工判断。
- 拆分结果若并入海报已有明确大类，`theme_rank` 继承该大类原位次；若形成海报未单列的新题材，`theme_rank=null`，不得借“其它概念”的容器位次伪造前二风口资格。

人工结论写入 `data/ths/strong_wind_manual_reviews.json`。禁止恢复题材正则表、关键词映射表、自动建议器或另一套公告分类表。
审核账本只在构建阶段使用；正式节点读侧不得读取它。`theme_rank`、`poster_rank`、`poster_group` 与 `theme_assignment` 必须落入当天 `strong_wind` 日文件，保证运行时仍只有一个题材真相输入。

## 四、数据流

```text
同花顺官方长图
  -> OCR 原文与明确分组
  -> “其他概念”逐股人工审核
  -> data/ths/strong_wind/YYYY-MM-DD.json
  -> 同花顺节点与进攻/防守模型

客观行情缓存
  同花顺涨停池 + 同花顺个股实际交易日
  -> current boards + 首封/终封/炸板次数 + 板型/真一字
  -> 梯队高度与防守锚

站点展示
  同花顺节点与进攻/防守模型
  -> ultraboard.ths.site_export
  -> site/public/data/ths-nodes.json
  -> 页面只读展示，不在前端或数据库重新推断
```

## 五、正式入口

```powershell
# 生成/回刷同花顺逐日真相
python tools/build_ths_strong_wind.py --start 2025-10-01 --end 2026-07-31 --workers 1 --overwrite --strict

# 旧文件只回写归属来源和海报原位次，不重跑股票 OCR
python tools/build_ths_strong_wind.py --all --provenance-only --workers 1 --strict

# 生成/回刷同花顺客观涨停池
python -m ultraboard.ths.limit_pool --start 2025-10-01 --end 2026-08-06 --force

# 列出节点日和冻结梯队
python -m ultraboard.ths.ladder_selector list 2025-10-01 2025-12-31

# 生成站点派生快照
python -m ultraboard.ths.site_export 2025-10-01 2025-12-31 --output site/public/data/ths-nodes.json
```

旧的第二来源采集链、旧站点评分/竞价快照及其派生结果已全部删除。
