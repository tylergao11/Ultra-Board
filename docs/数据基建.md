# Ultra-Board 数据基建

> 当前合同：同花顺“最强风口”是唯一题材真相；其他来源只能补客观行情事实。

## 一、真相源

| 数据 | 唯一来源 | 允许用途 |
|---|---|---|
| 当天主分组 | `data/ths/strong_wind/YYYY-MM-DD.json` | 个股题材身份 |
| 分组顺序 | 同上 `groups[].rank` | 进攻模型前二风口 |
| 公告身份 | 同上明确公告分组，或“其他概念”人工审核后的“公告题材” | 排除公告高度、节点日与选层 |
| 原图证据 | 同上 `source_image` 指向的同花顺官方长图 | 人工复核 |
| 连板数 | `data/kaipanla/raw/YYYY-MM-DD/zt_pool.json` 的 `boards` | 纯客观梯队高度 |
| 真一字 | 同上 `open/high/low` | 防守模型一字锚 |
| 首封、终封、炸板次数 | 同日客观行情文件 | 人工过程核对，不改变题材 |

开盘啦原始文件里的 `theme`、`sector_ladder`、概念列表和公告分类均已退出正式数据流。它们可以作为未加工的历史采集记录存在，但任何节点、选层、进攻/防守模型代码都不得读取。

## 二、同花顺逐日结构

```json
{
  "date": "2026-08-06",
  "source": "tonghuashun_strong_wind",
  "source_image": "data/ths/strong_wind_images/2026-08/20260806.png",
  "groups": [
    {
      "rank": 1,
      "title": "并购重组",
      "stocks": [{"code": "603221", "name": "爱丽家居"}]
    }
  ],
  "issues": []
}
```

读侧硬门禁：

1. `date`、`source`、`source_image` 必须有效，原图必须存在。
2. `rank` 必须从 1 连续递增；股票代码、名称必填，同日只能有一个主归属。
3. `issues` 必须为空。
4. 最终数据不得残留“其他”“其他概念”“其它概念”或“未分类”。
5. 当天客观涨停股必须全部能在同花顺主分组中找到。

## 三、人工审核

OCR 只负责还原图片和列出兜底分组的事件原文。对“其他概念”必须逐图、逐股找真实封板驱动：

- 独立公司事件驱动，如拟收购、资产注入或并购预期、控制权变更、业绩预增等，统一填写“公告题材”。
- 随当天行业或概念板块联动，填写真实自然题材。
- 不能只看字面。拿不准时结合当天热点、同板块涨停、封板时间与跟随关系人工判断。

人工结论写入 `data/ths/strong_wind_manual_reviews.json`。禁止恢复题材正则表、关键词映射表、自动建议器或另一套公告分类表。

## 四、数据流

```text
同花顺官方长图
  -> OCR 原文与明确分组
  -> “其他概念”逐股人工审核
  -> data/ths/strong_wind/YYYY-MM-DD.json
  -> 同花顺节点与进攻/防守模型

客观行情缓存
  -> boards + open/high/low
  -> 仅参与梯队高度与真一字计算
```

## 五、正式入口

```powershell
# 生成/回刷同花顺逐日真相
python tools/build_ths_strong_wind.py --start 2025-10-01 --end 2026-07-31 --workers 1 --overwrite --strict

# 列出节点日和冻结梯队
python -m ultraboard.ths.ladder_selector list 2025-10-01 2025-12-31
```

旧开盘啦题材分析链及其派生结果已全部退出系统。
