# Ultra-Board 数据基建

当前阶段只保留互不越界的数据源与事实查询入口，不保存交易模型及其派生结论。

覆盖审计入口：

```powershell
python tools/data_foundation.py --start 2025-10-09 --end 2025-12-31
```

该入口只报告各日期的数据是否存在，并给出已记录的竞价快照数量。
缺少故事表示“尚未生成或录入”，不能解释为当天没有市场故事。

## 一、来源职责

| 数据 | 唯一来源 | 边界 |
|---|---|---|
| 当日供应商粗分类 | 开盘啦 `zt_pool.json/stocks[].theme/themes` | 原样保留，不当成完整属性，尤其不据此删除首板 |
| 完整概念、地域与行业 | 同花顺 F10 `stock_profiles` | 仅采集接口最新交易日的当前快照，不回填历史成员关系 |
| 最近一期股本 | 同花顺 F10 `equity.html` | 只选择报告/变动日不晚于目标日的最近一列 |
| 题材梯队原文 | 开盘啦 `sector_ladder.json` | 源顺序不是交易结论 |
| 日级市场叙事 | 同花顺故事 v1 长图或 v2 官方复盘页 | 只作供应商收盘复盘归因 |
| 逐股市场故事 | v1 长图个股行或 v2 涨停池 `reason_type` 原文 | 保持原文，不拆分为题材 |
| 股价、市值与板上过程 | 同花顺 `limit_pool` | 提供股价、流通/总市值、换手率、封单、身位及封板过程 |
| 触板但收盘未封 | 同花顺 `open_limit_pool` | 与涨停池共同构成当日布局观察股票集合 |
| 秒级动作 | 东方财富 `intraday_ticks` | 最近交易日约三秒样本；相关性不是因果结论 |
| 情绪与表达快照 | 开盘啦 `sentiment.json`、`expression.json` | 保留原文，不在源层解释 |

## 二、开盘啦粗分类合同

日目录：

```text
data/kaipanla/raw/YYYY-MM-DD/
  zt_pool.json
  sector_ladder.json
  sentiment.json
  expression.json
  plate_info.json  # 可选
  _DONE
```

`zt_pool.json` 的每只股票必须保留：

- `theme`：开盘啦主分类，来自原始数组下标 5。
- `theme_tags_text`：开盘啦全部具体分类原文，来自原始数组下标 12。
- `sector_code`：开盘啦分类代码，来自原始数组下标 19。
- `raw`：完整原始数组，用于来源审计。

统一读入口为 `ultraboard.kaipanla.load_day()`；它只拆分开盘啦原文并生成 `themes`。这些字段是可审计的供应商标签，不是完整概念真相源。

动态归因时不得因为开盘啦未列出某个概念就删除该股票。应先用同花顺 F10 补全概念和地域，再结合当日故事与资金时序判断市场实际选择了哪个身份；任何推断都不得回写或覆盖开盘啦原始字段。`tools/extract_attribution_evidence.py` 只负责审计开盘啦标签、板上行为和上午/下午后继序列，不负责评分或自动归因。

## 三、同花顺故事合同

`data/ths/stories/` 支持两个闭合来源合同。历史 v1 继续读取 `data/ths/strong_wind_images/` 中人工核对的“最强风口”长图；新增日默认由官方历史复盘页与涨停池 `reason_type` 生成 v2。

```json
{
  "date": "2026-08-06",
  "source": "tonghuashun_strong_wind_headlines",
  "source_image": "data/ths/strong_wind_images/2026-08/20260806.png",
  "stories": [
    {
      "source_position": 1,
      "story": "市场并购重组持续活跃；龙头十连板",
      "context": "并购重组",
      "headline": "并购重组：市场并购重组持续活跃；龙头十连板"
    }
  ]
}
```

v2 把日级 `market_story` 与平铺 `stock_stories` 分开，避免把全部股票挂在同一个市场看点下。`block_1890/1891`、`context`、原图顺序和 `reason_type` 都不能成为具体题材分类或风口排名。逐股故事完整覆盖是正式导出的必要条件。

## 四、同花顺涨停池合同

`data/ths/limit_pool/YYYY-MM-DD.json` 只负责：

- 股价、涨幅、流通市值与可用时的总市值；
- 换手率、封单金额、封单数量与封单/流通市值比；
- 当前连续板数 `boards`；
- 同花顺窗口描述 `boards_desc`；
- 首封、终封和炸板次数；
- 板型与真一字；
- 连板倒推的客观日期证据。

涨停池事实投影不携带 `reason_type`；故事采集器可以从同一官方端点独立读取其原文。两者都不得使用 `reason_type` 读取或生成题材，也不得生成交易结论。

## 五、完整属性与秒级时序合同

`data/ths/stock_profiles/YYYY-MM-DD.json` 覆盖当日涨停池与炸板池并集，保存同花顺 F10 的完整概念解释、所属地域、申万行业、办公地址和股本结构。F10 没有指定历史日成员快照，因此采集器强制要求目标日等于接口最后交易日，并记录实际 `information_cutoff`；股本页若存在未来生效列，必须跳过并选择目标日以前最近一列。

`data/eastmoney/intraday_ticks/YYYY-MM-DD.json` 保存同一股票集合约三秒一条的价格与成交样本，并从价格重新导出触板/离板转换。它只允许采集接口最近交易日。`tools/intraday_window.py` 用于查看某个身位票开板前后，全体候选中还有谁在冲板、触板或显著加速；同一秒附近出现动作只是排查范围，最终仍要区分共同新闻、板块先启动、候选先动作和真正的跨梯队新增需求。

## 六、数据流

```text
开盘啦接口 -> 当日粗分类 + 题材梯队 + 情绪原文
同花顺长图或官方复盘页 -> 日级市场叙事
同花顺长图个股行或 reason_type -> 逐股市场故事
同花顺涨停池 -> 连板与封板过程事实
同花顺 F10 -> 最新交易日完整概念 + 地域 + 行业 + 目标日前最近一期股本
东方财富分时 -> 最新交易日涨停/炸板股票约三秒动作

各层事实 -> 只供查询与人工复盘使用，不自动生成布局答案
```
