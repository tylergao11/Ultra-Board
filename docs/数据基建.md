## 本次批量补齐与统一离线入口（2026-09-15）

- 无人值守总入口：`python tools/replay_complete.py`。脚本自行初扫、按缺项补采、有限重试、最后汇总；默认每项最多尝试两次，已有有效缓存直接复用。
- 已有成员批次运行时，用 `--wait-pid 实际进程号` 接续，等待结束后再补其余缺项，不重复启动。运行状态为 `data/replay/complete_state.json`，日志为 `data/replay/complete.log`，最终缺项为 `data/replay/coverage.json`；仍有缺项返回退出码 2，不宣称已补齐。
- 补齐命令：`python tools/replay_backfill.py all`。默认从已有最早涨停池日期开始，到北京时间已收盘的最近交易日；节假日使用 `data/calendar` 中上交所原始休市公告。接口未入库会报缺口，不登记成休市。
- 可分别续跑 `kpl`、`market`、`attack-times`、`prices`、`price-gaps`、`references`、`members`；已有成功缓存跳过。`audit` 输出当前范围的缺口，不把 `_DONE` 当作所有字段齐备。
- 统一查询：`python tools/replay_query.py YYYY-MM-DD --code 股票代码 --plate 板块编号`，代码和板块参数均可省略。此入口只读本地，绝不隐式联网。
- 用户最新定义：需要“有没有进攻涨停”和“第一次进攻涨停时间”，不再要求逐次开板、回封流水。字段为 `has_limit_attack`、`first_limit_attack_ts`、`first_limit_attack_time`；竞价和盘中用 `first_limit_attack_session` 区分。时间取来源首次触板，不用最终封板时间替代。
- 历史催化：开盘啦 `GetPlateInfo_w38 / HisLimitResumption`，参数 `Date`，保存到原有 `history_limit_resumption.json`。与只返回最新日的 `DailyLimitResumption` 不同。
- 完整成员：复用旧快照；补采实测 `ZhiShuStockList_W8` 的 `Type=20, st=1000` 可完整分页，仍逐页核对日期、代码唯一性和总数。旧记录中 `Type=6, st=1000` 的空响应不适用于这组参数。
- 未封住股票的首次触板使用已有同花顺炸板池。开盘啦新版历史 `HisDaBanList / HisHomeDingPan`（`PidType=2, Type=6, apiv=w45`）原始行第6项不能认作首次触板：接口解析资料标为最后涨停时间，且存在晚于打板客事件时间的记录。该值只保存在 `kaipanla_reported_limit_ts`，不填充首次进攻时间；原始响应保留。
- 价格：同花顺 `/v6/line/hs_{code}/00/{year}.js` 未复权行情。旧 `/01/` 前复权缓存保留，不能冒充未复权价格。来源空价格行保留为缺项，不丢弃同年其他有效行情。
- `data/replay/market`、`prices`、`breadth` 是统一日查询数据；各自原始响应留在供应商目录。显示涨幅反算参考价时枚举所有符合舍入区间的分币价格，唯一解可写入 `open_pct`。
- `references` 为缺少参考价或需要替换打板客反算值的股票读取同花顺 `basic.10jqka.com.cn/{code}/bonus.html` 分红配股日期，缓存于 `data/ths/corporate_actions`。前次交易至当日没有来源记录的除权日、历史表覆盖到对应年份时，直接使用同花顺前收盘价，不专门记录或追查补缺源差异；涉及除权或资料不足时保留缺项。重建价格索引后应运行此步骤；`all` 已包含它。
- 同花顺确实缺失的价格由腾讯未复权 `day` 数据补缺，单独保留来源于 `data/price_checks/missing_unadjusted`；已确认停牌记录位于 `data/replay/trading_status`，不伪造停牌日报价。
- 停牌记录使用同花顺 `http://search.10jqka.com.cn/thsft/iFindService/StockCalendar/index/detail?code={code}&date={date}`，从停复牌提示页的历史明细入口获取；原文保存在 `data/ths/suspensions`。`status` 仅查询缺报价的股票日期，按明确停牌、复牌时间判断是否覆盖全天；`all` 已包含该步骤。
- 当前批次尚在补采；实际覆盖与错误见 `data/replay/coverage.json`、`price_errors.json`、`member_errors.json`，不能把上述命令存在理解为全量完成。

交易讨论只以根目录AGENTS.md及用户最新指示为准。本文件只定义数据怎么取、字段是什么意思。

## 来源边界（2026-09-15 确认）

- 属性、消息催化、板块异动解释、细分成员和细分涨停数量，只用开盘啦，其他网站不得替代。先读取对应一字板的开盘啦复盘催化原文，再确定细分并计数。
- 打板客可以提供封板、开板、回封时间、板型、价格等行情事实；其属性分类、涨停原因和概念统计不用于本轮判断。
- 下文保留的其他供应商接口和历史核验记录，只说明已有数据。它们不构成属性或消息来源授权。缺少开盘啦对应原文时应标明缺口，继续查开盘啦，不得换源补成交易结论。

## 缓存和核验

- `data/kaipanla/raw/YYYY-MM-DD/zt_pool.json`：当天涨停池，原有唯一来源。
- 同目录`limit_ladder.json`：供应商涨停天梯原始返回，补充一字标记。
- `data/kaipanla/plate_members/YYYY-MM-DD/板块编号.json`：完整成员及原始分页。
- `data/kaipanla/concepts_current/抓取日期/股票代码.json`：当前属性与编号查询缓存。
- 日期、代码唯一性、分页总数和交集股票价格需一致。空响应报缺口，不能输出零只。
- 成员接口st=1000曾返回成功码但空列表；已采用实测可用的50条分页，不重复探测。
- 成员接口中的历史行情日期可验证，附带名称、标签和成员关系是否存在后补没有完整保证；保持`historical_membership_verified=false`，不宣称绝对不漂移。
- 天梯第6项的供应商含义为“大单一字”标记。1直接记录为有标记，0记录为未标记；不能另造“大单封单阈值”，也不能将0冒充独立证明非一字。个别来源冲突才抽查，不能重新铺开逐股日线工程。
- 实测：顺钠2024-12-31标记1，2025-01-02标记0。两日数据中心交集为8只、5只，完整名单见接续记录。
- `GetPlateInfo_w38`是最新涨停原因列表，会忽略历史日期，不能替代历史成员接口。`GetDayZhangTing`本次也未按传入日期定位，不作为指定日板型查询。
- `HisDaBanList`当前封装的PidType=2为炸板列表，不是完整涨停池；不能拿它的空值或数量代替上述正式涨停池。

### 建议的最小来源组合

| 内容 | 主要来源 | 补充与边界 |
|---|---|---|
| 题材名称、板块编号、完整成员、细分涨停数量 | 仅开盘啦 | 保存每次取得的版本；粗分类、附带标签、完整成员分开；按完整成员与当日涨停池取交集，不按多家标签拼接，也不因成员另有属性或催化而剔除 |
| 每日涨停名单、连板数、基础行情 | 开盘啦直接涨停池 | 同花顺用于异常或缺口核对，不要求每次为同一批字段重复全量采集 |
| 一字与接力过程 | 开盘啦标记；打板客可提供行情核对 | “大单一字=0”不等于确定非一字；精确板型、末封、开板次数须记录实际来源，不由行情来源推导属性或催化 |
| 炸板失败 | 先保留已通过日期校验的同花顺炸板池 | 开盘啦现有封装尚不可用；早期缺口查打板客并记录来源，不能仅凭网页可读便声称完整批量采集已具备 |
| 涨停原因、催化 | 仅开盘啦当日复盘及对应催化原文 | 核对一字板与首、二板起步时的消息，按消息实际推动的细分归类；缺少原文标明缺口，不用其他复盘替代，不输出确定的做或不做结论；行情事实可继续查询 |
| 交易日 | 交易所休市安排与可校验的交易日历 | 不能把周一至周五全部当交易日，也不能把本地相邻两个文件夹当成相邻交易日 |
| 分时、全套 F10、龙虎榜等辅助资料 | 按具体页面需要取数 | 不作为第一版核心连续复盘的每日必备项 |

交易日依据：[上交所 2026 年休市安排](https://www.sse.com.cn/disclosure/dealinstruc/closed/c/c_20251222_10802510.shtml)、[深交所 2026 年部分节假日休市安排](https://investor.szse.cn/disclosure/notice/general/t20251222_618087.html)。

### 调整顺序

1. **先保护连续性。** 每份记录保留交易日期、实际抓取时间、来源接口与参数、原始响应；复抓保留新版本，不覆盖先前版本。历史补采标为补采，不能冒充当日快照。股票使用代码身份，题材使用供应商编号；名称变化单独记录。分类口径调整与股票新涨停分别记录，不能把标签扩容直接当成市场加强。
2. **补齐失败状态与日历。** 每日同时覆盖涨停与触板未封；对昨日仍在跟踪、今天不在两池中的股票保留记录，核实交易状态，缺数据不直接判作断板。按交易日历显示缺失日，禁止跨过缺口悄悄连接为连续两天。
3. **收窄核心更新。** 核心行情、板块成员、失败状态按各自完整性发布；某板块成员不全时不计算它的宽度变化。消息或辅助资料缺失仅影响相应模块，不把整日行情一起判作不可用。先保证正在追踪的题材能够逐日取得完整成员，再扩展覆盖。
4. **移除重复的强制依赖。** 核验覆盖足够后，再将同花顺涨停池、完整 F10、东方财富秒级分时改成按需补充。当前 `daily_update.py`、`day_facts.py` 的完整性判断及日期选择仍依赖多个来源，不能只删缓存或跳过某一步便宣称迁移完成。

现有代码中，`day_facts._neighbor_day` 使用已有数据日期列表，遇到所有来源均缺失的一天会跳过；`kaipanla.backfill.trading_days` 只筛选工作日。这两处需要在网站连续回放接入时改用真实交易日历。本次只完成来源核验和方案记录，没有修改上述运行逻辑。


## 2026-09-15 批量数据交付口径

- 本轮仅处理数据，不执行交易复盘。
- `python tools/replay_complete.py`：按交易日历扫描缺项、补采、最终汇总；默认以北京时间16点作为当日收盘数据更新分界。
- `python tools/replay_query.py YYYY-MM-DD`：统一离线查询。
- 当前已整理范围：2024-07-22 至 2026-09-14，共523个交易日。
- 用户确认炸板首次触板时间取不到可留空；炸板名单与触板状态保留，已取得的时间保留，不再为这些空值追补或阻塞完成。
- 必需缺项在 `data/replay/coverage.json` 的 `gaps`；允许的空值在 `optional_missing.failed_limit_first_touch_time`。封住涨停的首次封板时间仍属必需字段。
- 历史补采是来源当前返回的历史记录，不等同于当日保存的原始快照。


## 个股中心存储与清理（2026-09-15）

- 成员关系：`data/kaipanla/stock_memberships/YYYY-MM-DD.json`，`stocks[股票代码]`只存所属细分编号列表。`plates`仅保留成员总数和采集时间，不保存成员行情。
- `replay_query.py`按代码组织行情、催化与细分关系；查询细分数量时动态计算成员关系与开盘啦涨停池的交集。历史是否属于当日原貌仍取决于来源，迁移不改变这个边界。
- `python tools/compact_replay_data.py --apply`：逐日检查原始分页、旧成员列表与新成员关系完全相同，写入后重新读取验证，再删除旧的板块成员JSON和可重算的细分数量缓存。中断可续跑；不联网。
- 不带`--apply`只报告；`--day YYYY-MM-DD`可限定一天。保留价格、涨停池、炸板名单、催化等有效数据。

## AI 离线接口（当前合同）

准确、便捷、无冗余优先于人工排版。以下合同替代上文关于永久保留重复响应、派生缓存的旧建议。

```python
from tools.replay_query import query
query("2025-03-31", pool="one-price", fields=("code", "open_pct", "first_limit_time"))
query("2025-03-31", code="六位股票代码", fields=("code", "catalysts", "plate_ids"))
query("2025-03-31", plate="六位细分编号", pool="limit", fields=("code",))
```

命令行：`python tools/replay_query.py 日期 --pool one-price --fields code,open_pct,first_limit_time`。

- `pool`：`limit` 为开盘啦涨停池，`failed` 为炸板，`one-price` 为行情明确标识的一字板。不指定则为已存行情、涨停池及价格记录的股票并集。
- `fields`：`code,name,boards,board_type,closed_limit,failed_limit,open,close,open_pct,first_limit_time,final_limit_time,open_count,plate_ids,catalysts,has_limit_attack,has_reseal,first_limit_ts`。默认不读取催化原文或成员关系；请求后才加载。
- 日期、代码为字符串；价格及涨幅为数字，涨幅单位为百分数；时间为北京时间 `HH:MM:SS`，时间戳为 Unix 秒。只请求一种时间格式即可。
- `null` 表示字段未知；不存在记录返回空股票列表。`missing_components` 标明所需数据组件缺失，不能把缺失成员关系当成真实零数量。
- `catalysts` 中的 `group` 指向顶层 `catalyst_groups`，组名与完整解释只返回一次；个股保留其催化原文。仅用开盘啦。
- `plate.limit_count` 始终是完整成员与同日开盘啦涨停池的交集数量，包含股票自身。`stocks` 则遵循本次 `pool` 筛选。
- `has_reseal` 由开板次数及收盘状态推导；不能用首次触板、最后封板推定首次有效回封时刻。
- 首次时间优先用统一行情记录，再用开盘啦已明确的首次字段补缺；价格来自同花顺未复权记录及已保存参考价。不得用未经确认语义的历史字段替代首次时间。
- 历史成员关系来自供应商补采版本，不能视为交易当日保存的原貌；对应状态见成员文件和覆盖报告。

存储：价格按年份分库，唯一键 `(股票代码,交易日)`；旧年行情和日价格文件仅保存映射。市场事实去掉可无损还原的重复时间与状态，来源信息用索引引用。打板客网页已转成指向统一行情的引用；同花顺分红解析结果保留，网页正文及无用图片不保留。

读取这些映射统一使用 `ultraboard.kaipanla.query._read`，不得直接将 `json.loads` 的结果当完整行情。数据补采继续使用 `tools/replay_complete.py`，不在查询时联网。

`python tools/clean_fact_duplicates.py --apply` 负责价格、行情和网页副本清理；`tools/compact_replay_data.py --apply` 负责旧板块成员迁移。均可续跑，写入并回读验证后才替换副本。价格分库迁移由 `tools/split_price_store.py` 执行，逐表双向比对后移除旧单库。
